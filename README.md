# 知微 · 游戏策划 AI 知识工作台

> 一个 DSH 插件：把策划的设计结论、规则、假设、问题、方案、参考、数值和复盘，整理成**有类型、有状态、有来源、有版本、有语义关系**的记忆。AI 负责观察、沉淀、订正、连关系，你负责确认与拍板；重要约定默认锁死，永远由你决定。

之前的名字是「策划记忆」（1.x）。2.0.0 起叫**知微**，内部包名与数据目录保持不变，旧数据自动迁移。当前版本 **2.1.0**：记忆会随使用持续演进（版本 / 证据 / 提案），关系网自动生长，并新增整理中心与调用记录。见 [CHANGELOG](docs/CHANGELOG.md) 与 [升级说明](docs/UPGRADE-2.1.0.md)。

## 它解决什么问题

策划的知识散在聊天、文档、表格和脑子里。三个月后你会遇到这些情况：这条数值还生效吗？当时为什么这么定？改这个会不会影响别的系统？新方案和旧方案是冲突还是替代？

知微给每条知识一个结构化外壳，并让 AI 负责整理、你负责确认：

- **类型**回答「这条是什么」：设计决策 / 设计规则 / 设计假设 / 设计问题 / 设计方案 / 参考案例 / 数值数据 / 复盘结论 / 流程约定。
- **领域**回答「属于哪块业务」：战斗、成长、经济、关卡、活动、UI/UX、商业化、社交、运营、技术约束，可多选。
- **状态**回答「能不能用」：草稿 / 待确认 / 已生效 / 已废弃 / 已归档。
- **来源**回答「从哪来」：手动 / 对话 / 导入 / AI 整理。
- **关系**回答「和谁有关」：归属于 / 依赖于 / 影响 / 来源于 / 参考 / 冲突 / 替代 / 细化，有方向、有置信度、有确认状态。\n- **版本与证据**回答「凭什么信」：每次修改留新旧内容、原因、证据与来源对话；可以回滚、可以追溯。\n- **保护级别**回答「能不能被 AI 改」：普通 / 已确认 / 固有约定。固有约定最高保护，AI 只能提示矛盾，不能自己改。

## 功能

**三栏知识工作台**：左导航（项目空间、全部记忆、待整理、主题集合、收藏、最近访问、关系图、保存的视图）、中内容区（搜索、筛选、列表/卡片、概览）、右详情栏（类型状态、来源、正文、领域、集合、按类型分组的关系、AI 辅助、改动记录）。两栏可折叠，窄屏自适应。

**快速新增**：粘贴一段原文，自动得到标题、摘要、类型、领域、标签、原子化拆分建议与相关集合；一键应用或直接保存。AI 整理过的内容默认落在「待确认」。

**记忆列表**：搜索 + 项目/类型/领域/状态/标签联合筛选，列表或卡片，按更新时间/创建时间/标题排序，多选批量操作（加入集合、改状态、删除）。

**主题集合**：手动创建、批量加成员、移出、改名改简介、合并、拆分；AI 聚类建议带名称、简介与归类理由；集合页一键生成主题总结。

**关系图**：分簇自动布局、节点拖拽（只改显示，不改数据）、集合边界与折叠、按类型/关系/领域/集合筛选、搜索定位、点击开详情、按关系类型区分线型与箭头、框选批量操作、保存视图、深浅色适配。

**AI 辅助**（本地启发式，全部附理由）：整理这条、找相似、推荐关联、查冲突、上下游分析、主题总结。AI 只给建议，不会自动把假设升格成规则，也不会擅自覆盖旧数据。

**操作反馈**：统一 toast、进行中/完成态、删除二次确认、空状态引导、错误文案；删除记忆或集合后在 toast 里可撤销，连同关系与集合归属一起恢复。

**自动沉淀（2.1）**：顶栏 ✨ 粘贴一段对话，host 逐条对比已有记忆——能覆盖的只补证据，能细化的写新版本，和已确认内容冲突的转成更新提案，全新的建「待确认」候选并自动连关系，一次性的内容直接跳过。

**棘轮演进（2.1）**：版本历史 + 证据链 + 提案机制。普通补充直接写新版本并留痕；与已确认内容冲突时不覆盖，生成提案等你确认；AI 推测只能做候选。可以回滚到任意旧版本，且回滚本身也会记一个版本。

**固有约定保护（2.1）**：项目固定规则、术语规范、长期输出标准这类记忆可标为「固有约定」。AI 只能提示矛盾或过时，正文改动一律被拒绝（`409 protected`），只有你能改、能解除、能废弃。

**自动关系网（2.1）**：新建/更新/合并记忆后增量推荐关系，带置信度与来源；建议中的关系是虚线，被否决的不会无缘无故重建。关系图里选中节点会高亮它的上游与下游。

**整理中心（2.1）**：待确认提案、待确认关系、疑似重复（一键合并）、孤立记忆、待复核条目集中在一页处理。

**调用记录（2.1）**：智能体按任务检索记忆（`design_memory_recall`）时，取用了什么、什么时候取用都记下来，并累加记忆的调用次数；左栏可查。注：不提供聊天消息的自动注入（见「限制」）。

## 安装

```bash
dsh plugin add github:ivezhang/dsh-GameDesignMemory
```

或把仓库克隆到插件目录，在 `cordis.patch.yml` 里插入：

```yaml
- insert:
    - id: design-memory
      name: '@local/design-memory'
```

安装后重启 DSH，左侧栏出现「知微」。

## 用起来

1. **记录**：点左上「新建记忆」，把脑子里那段话直接粘进去 →「AI 整理」看建议 →「保存」。不想被整理就「只保存」。
2. **确认**：在「待整理」里把草稿改成待确认/已生效；确认过的规则才是规则。
3. **归类**：到「主题集合」让 AI 提聚类建议，接受有用的，改名改简介，把不合适的移出去。
4. **探索**：打开「关系图」，按领域/类型筛选，点节点看详情；用「划线」建立语义关系；框选一组记忆直接建集合；把当前视图保存下来下次一键回来。
5. **和 AI 一起用**：在对话里让智能体用 `design_memory_search` / `design_memory_write` / `design_memory_suggest` / `design_memory_analyze` 帮你检索、整理与归纳。
6. **让它自己长**：把一段对话贴进顶栏 ✨（或让智能体调 `design_memory_observe`），然后去「整理中心」处理提案与待确认关系。重要约定标成「固有约定」，AI 就不能改了。
7. **按任务取用**：新对话开工时让智能体调 `design_memory_recall`，它会按「项目已确认约定 → 相关项目记忆 → 全局习惯 → 其他」分层返回，受保护条目会明确标注。

## 数据与备份

- 位置：`%DSH_HOME%/design-memory/memories.json`（默认 `C:\Users\<你>\.dsh\design-memory\`），当前版本 4。
- 每次写入前保留 `memories.json.bak`；写入用临时文件 + 原子改名；坏文件改名 `.corrupt-<时间戳>`，不静默丢数据。
- 备份就是复制整个目录。

## 目录结构

```
index.js            host：存储、迁移、演进引擎、六个工具、HTTP 接口

docs/CHANGELOG.md   更新记录

```

## 兼容性与限制

- 无第三方运行时依赖，无构建步骤；host 是 Node ESM，前端是浏览器模块（只依赖 `react`）。
- 支持浅色/深色主题，跟随 DSH。
- 分析引擎与观察引擎都是规则化启发式，不是大模型：不做语义向量检索；AI 不会静默改已确认内容。
- 单机数据，暂无多用户协作与云同步。
