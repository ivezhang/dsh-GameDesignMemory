# 知微 · 给游戏策划的记忆与知识网络

> **你做的不是文档，是判断。判断需要被记住、被追溯、被别人（和 AI）理解。**
> 知微把策划脑子里、对话里、表格里的结论沉淀成有类型、有状态、有来源、有版本、有关系的知识；AI 负责观察、整理、连关系，**你负责拍板**。
> 重要约定默认锁死，AI 永远改不动。

当前版本 **2.8.1** · 数据版本 6 · DSH 插件 · MIT

---

## 一、核心理念

**1. 记忆不是仓库，是活的判断。**
把结论丢进文档，它就死了。知微里的每一条知识都会随使用演化：补充写新版本、冲突转提案、被替代留指向、被调用记次数。三个月后你看到的不是「一段旧文字」，而是「这条判断怎么一步步走到今天的」。

**2. AI 可以整理，但不能替你做决定。**
AI 在这个系统里的位置是**助理研究员**，不是主人。它观察、比对、提候选、连关系、给理由；它不可以把假设升格成规则，不可以静默覆盖已确认的内容，不可以动你标了「固有约定」的东西——那是代码级的 409。**信任不是靠提示词，是靠机制。**

**3. 一条知识值多少钱，看它和谁有关。**
孤立的记忆是笔记，连起来的记忆才是系统。「这个副本掉落什么」「这把剑由什么做出来」「这条数值被哪个系统依赖」——关系有方向、有类型、有置信度、有确认状态。知微把「记忆 + 知识对象 + 关系」做成三层模型：对象描述稳定的东西（系统、怪物、流程、偏好、原则），记忆描述发生的判断，关系把它们连成一张能查询的网。

**4. 三个月后还能不能信，取决于有没有留痕。**
每次改动都留：改了什么、为什么改、证据是什么、谁改的、从哪次对话来的。可以回滚到任意一版，回滚本身也算一版。**宁可留痕，不要静默覆盖。**

**5. 你的知识应该长在项目上，而不是长在聊天窗口里。**
对话会关掉、模型会换掉、工具会过时。知微的数据是**本地一个 JSON 文件**，可导出、可导入、可迁移、可备份、可整库带走。没有账号、没有云、没有订阅；换台机器复制一个目录就搬家。

**6. 结构化不是给人添麻烦，是把麻烦交给机器。**
你只管把想到的话粘进来。标题、摘要、类型、领域、标签、该拆成几条、该连哪条——让 AI 先猜，你只做选择题。**人的时间应该花在判断上，不是花在填表上。**

## 二、它解决什么

策划的知识散在聊天、文档、表格和脑子里。三个月后必然遇到这些追问：

- 这条数值还生效吗？
- 当时为什么这么定？
- 改这个会不会踩到别的系统？
- 新方案和旧方案是冲突、替代，还是同一件事的两种说法？
- 这条规则是我拍板的，还是 AI 猜的？

知微给每条知识一个结构化外壳，并且**让「谁说了算」变得可见**：

| 维度 | 回答的问题 | 取值 |
| --- | --- | --- |
| 类型 | 这条是什么 | 设计决策 / 规则 / 假设 / 问题 / 方案 / 参考 / 数值 / 复盘 / 流程约定 / 用户习惯 / 通用约定 / 项目背景 / 临时事项（13） |
| 领域 | 属于哪块业务 | 战斗、成长、经济、关卡、活动、界面交互、商业化、社交、运营、技术（10，可多选） |
| 状态 | 能不能用 | 草稿 / 待确认 / 待复核 / 已生效 / 已废弃 / 已归档（6） |
| 保护级别 | AI 能不能改 | 普通 / 已确认 / 固有约定（锁定，只能人改）（3） |
| 来源 | 从哪来 | 手动 / 对话 / 导入 / AI 整理（4） |
| 版本与证据 | 凭什么信 | 每次改动的类型、原因、证据、时间、来源对话（可回滚） |
| 关系 | 和谁有关 | 28 种有向关系，分五组：层级 / 业务 / 流程 / 偏好与原则 / 通用 |

## 三、三层模型：记忆、对象、关系

**记忆（Memory）** 承载具体判断：这条规则、这个数值、这次复盘。

**知识对象（KnowledgeNode）** 描述稳定的实体，共 8 类：项目、系统、子系统、业务对象（怪物 / 装备 / 技能 / 副本…）、工作流程、用户偏好、设计原则、设计方法。对象有属性（怪物写阵营定位、流程写触发与产出、偏好写倾向与避免）、有流程步骤（可拖拽排序）、有别名与标签、也有自己的版本历史。

**关系（Relation）** 两端可以是记忆、也可以是对象，共 28 种类型，分五组：

- **层级**：包含、属于、部分属于
- **业务**：出现在、使用、掉落、需要、由…制作、影响、依赖、平衡于
- **流程**：接续、先于、下一步、触发、产出、例外
- **偏好与原则**：偏好、避免、适用于、指导、约束
- **通用**：相关、来源于、参考、冲突、替代、细化

一条记忆可以挂多个对象，一个对象可以收多条记忆。关系**只用一种方式建**，在关系图里划线——没有第二处会偷偷改数据的入口。

## 四、界面：一个工作台，三种视角

**三栏结构**：左导航 → 中工作区 → 右详情。两栏都可折叠，窄屏自适应。

**知识网络（核心页）** 四个视图共用同一张画布，切换视图只改筛选、不复制节点：
- **项目结构**：从项目到系统到模块的层级骨架
- **工作流程**：有序步骤，步骤可拖动改序
- **用户偏好**：你反复表达的倾向与禁忌
- **全局知识**：跨项目复用的原则与方法

**记忆区**：在画布上直接画一个框，框里的节点就归属它；拖框时框里的记忆跟着一起走；框可以嵌套、可以连到别的框，用来搭「项目 → 系统 → 模块 → 规则」的空间结构；检索与召回都能限定在某块记忆区（含子框）里找。

**关系图**：记忆视角的全景，分簇自动布局、拖拽、筛选、搜索定位、保存视图、深浅色适配。选中一个节点会高亮它的上游与下游。

**整理中心**：待确认提案、待确认关系、疑似重复、孤立记忆、候选对象、重复对象集中在一页处理。**「AI 一键整理」** 会先给一份只读预览——打算合并哪几条、确认哪几条关系——你点确认才执行，整次可撤销。

**待整理 / 收藏 / 最近访问 / 调用记录 / 项目空间**：日常入口。项目空间支持右键改名与删除、拖动排序、多选后批量合并迁移（记忆、知识对象、记忆区、保存的视图一起搬走）。

**全局撤销**：`Ctrl / Cmd + Z` 退回上一步（顶栏也有按钮），删除类操作在提示里直接给「撤销」。

## 五、核心机制

**自动沉淀**：顶栏 ✨ 粘贴一段对话，host 逐条与已有记忆比对——能覆盖的只补证据，能细化的写新版本，与已确认内容冲突的转成更新提案，全新的建「待确认」候选并自动连关系，一次性的东西直接跳过。

**棘轮演进**：版本 + 证据 + 提案。普通补充直接落新版本并留痕；与已确认内容冲突不覆盖，而是生成提案等你确认；AI 推测只能当候选。可以回滚到任意旧版本。

**固有约定保护**：项目固定规则、术语规范、长期输出标准可以标为「固有约定」。AI 的静默修改一律返回 `409 protected`，只有你能改、能解除、能废弃。

**自动关系网**：新建、更新、合并后增量推荐关系，带置信度和来源；建议中的关系画虚线，被否决的不会无缘无故重建。

**按任务召回**：新对话开工时让智能体调 `design_memory_recall`，按「项目已生效的固有约定 → 本项目相关记忆 → 全局习惯 → 其他」分层返回，受保护的条目会明确标注「必须遵守」，并带召回路径（对象 → 关系 → 记忆）。

**跨对话续写**：同一件事的流程在第二次对话里补上新步骤，会合并进同一个流程对象并记一个版本，而不是长出第二个「差不多」的流程。

**数据安全**：每次写入前留 `memories.json.bak`；临时文件 + 原子改名；坏文件改名 `.corrupt-<时间戳>` 而不是静默清零；导出默认带知识对象，导入不会丢东西（这条 2.6.8 才发现并修掉，写在这里提醒自己：**数据完整性不验证就等于没有**）。

## 六、给 AI 用的六个工具

| 工具 | 用途 |
| --- | --- |
| `design_memory_search` | 按关键词 / 项目 / 类型 / 集合 / 记忆区检索 |
| `design_memory_write` | 新建或更新记忆、对象、关系、集合 |
| `design_memory_suggest` | 整理建议：建议标题类型标签、可拆的原子片段、推荐关联、可归的集合 |
| `design_memory_analyze` | 只读分析：相近、关系、上下游、集合总结、冲突检查 |
| `design_memory_observe` | 观察一段对话，自动对比、更新或生成待确认候选 |
| `design_memory_recall` | 按当前任务分层取回最该用的记忆，并记录一次真实调用 |

AI 整理结果默认落在「待确认」；受保护内容只能生成「修改建议」，等你说可以。

## 八、三分钟上手

1. **记一条**：点左上「新建记忆」，把那段话原样粘进去 →「AI 整理」看建议 →「保存」。
2. **确认它**：到「待整理」把草稿改成待确认 / 已生效；确认过的规则才是规则。
3. **搭骨架**：打开「知识网络」，先建项目对象，再建系统对象，用「划线」把系统挂到项目上。
4. **收记忆**：建几个知识对象（怪物、装备、副本），或者直接画一个记忆区，把相关记忆拖进去。
5. **让它自己长**：把一段对话贴进顶栏 ✨，然后去「整理中心」处理提案、待确认关系与疑似重复；觉得没问题就点一下「AI 一键整理」。
6. **重要的事锁起来**：把项目固定规则标成「固有约定」，从此 AI 只能提醒你矛盾，改不动它。
7. **新对话开工**：让智能体先调 `design_memory_recall`，它会先给你「必须遵守」的那几条。

**快捷键**：`Ctrl/Cmd+K` 搜索 · `Ctrl/Cmd+Z` 撤销 · `Space`+拖动 平移 · `Shift`+拖动 框选 · `Ctrl/Cmd`+点击 多选 · `Esc` 逐层退出 · `Delete` 删除选中（始终二次确认）

## 九、数据与备份

- 位置：`%DSH_HOME%/design-memory/memories.json`（默认 `C:\Users\<你>\.dsh\design-memory\`）
- 结构：`{ version, projects, entries, nodes, relations, collections, frames, layout, views, proposals, recalls, stats }`
- 上限：记忆 4000 / 对象 1200 / 关系 4000 / 正文 40000 字
- 迁移：v1 → v6 逐版自动迁移，迁移只搬不改；旧数据里没有的对象不会被凭空造出来
- 备份 = 复制整个目录；导出/导入是整库 JSON，也可以在项目空间右键只导出单个项目

## 十二、取舍与已知限制

- **AI 是规则化启发式，不是大模型语义检索。** 没有向量库、没有 embedding。好处是确定、可解释、不联网、不花钱；代价是「意思相近但用词不同」可能漏掉。
- **不做聊天消息自动注入。** 记忆怎么进、进哪条，由你和对话里的智能体显式决定，避免上下文被悄悄污染。
- **单机单文件。** 没有多用户协作、没有云同步。备份就是复制目录。
- **知识网络不是思维导图。** 画布定位是「理解结构」，不是画得很漂亮；超过 120 个节点不会自动聚合。
- **浏览器层的真实鼠标轨迹、滚动命中、动画观感** 由人工走查覆盖（清单见 `docs/WALKTHROUGH.md`），自动化测试只保证数据层与交互契约。

## 十三、版本路线

- **1.x 策划记忆**：结构化记忆、关系网、记忆区雏形
- **2.0 知微**：改名、13 类记忆、集合、三栏工作台、AI 建议
- **2.1 自动沉淀**：棘轮演进、版本、证据、提案、保护级别、整理中心、调用记录
- **2.2–2.3 空间化**：项目空间、记忆框 → 记忆区（容器、嵌套、区域检索）
- **2.4 设置与集合**：集合管理、视图可删、设置进 DSH 设置页、模型选择接通
- **2.5 知识网络**：知识对象 + 记忆双层、28 种关系、四维度视图、数据版本 6
- **2.6 自动化**：需求对照、场景演练、流程自动归纳与跨对话补全、性能（7.8s → 0.07s）、导出修复、全局撤销
- **2.7 修坑**：项目重命名/删除不再多建项目、删项目连带迁走对象与视图、老记忆框可选中可删除、项目批量合并
- **2.8 成整体**：记忆区变真容器（拖框带成员、退出不重排、窗口自适应）、AI 一键整理
