# 知微 · 架构说明

本文件说清「知微」是怎么搭起来的：它跑在哪、进程里分了哪几层、数据从哪来、怎么存、界面怎么接进来。面向接手维护的人和做评审的策划，不要求懂 DSH 源码。

## 一、它是什么

知微是 DeepSeek Harness（DSH）的一个**本地插件**，不是一个独立服务。装进 DSH 之后它同时提供两样东西：

1. **一个知识工作台界面**：三栏布局，左栏导航、中栏列表/关系图、右栏详情，作为 DSH 侧栏里的一个入口打开。
2. **六个给对话 AI 用的工具**：AI 在聊天里可以主动检索记忆、写入记忆、分析一条记忆该怎么归类、观察一段对话沉淀记忆、按当前任务召回、以及生成整理建议。

数据全部落在本机的一个 JSON 文件里，不外发、不联网（除非你手动在设置里切到别的模型服务）。

## 二、进程内分层

插件宿主代码跑在 DSH 的 Node 进程里，按职责分成 8 个文件，构建时按文件名顺序拼成单个 `index.js`：

| 文件 | 职责 |
| --- | --- |
| `00-head.js` | 常量、错误构造、通用小工具（类型/领域/状态/关系类型等枚举都在这里） |
| `10-normalize.js` | 所有落库数据的规范化与裁剪：读进来先过一遍，保证字段形状、长度、枚举合法，坏数据被丢掉而不是让界面崩 |
| `20-engine.js` | 存储引擎：定位数据文件、读写、串行化写入、原子替换、备份 |
| `25-assist.js` | 启发式建议引擎：从正文抽标签/领域/标题、找相似记忆、建议关系与集合。完全确定性，不调模型 |
| `28-evolve.js` | 演进层：版本推进、纠正、观察沉淀、按对象召回、整理中心报告、重复检测、流程归纳 |
| `30-store.js` | HTTP 接口层：读状态（GET）、执行操作（POST），以及布局、视图、导入导出的入口 |
| `32-knowledge.js` | 知识对象层：对象增改、关系双端点校验、对象与记忆的多对多挂接、合并、归档、版本回滚 |
| `40-apply.js` | 注册入口：把六个工具注册给 DSH、挂 HTTP 路由、注册设置页节区、注入系统提示 |

客户端是单文件 `client.js`，一个模块工厂，按 14 个分件拼成：

| 文件 | 职责 |
| --- | --- |
| `00-head.js` / `10-css.js` / `20-icons.js` / `30-utils.js` / `40-atoms.js` | 模块壳、样式、图标、请求与格式化工具、基础组件 |
| `50-rail.js` | 左侧导航栏（含项目空间、保存的视图） |
| `60-center.js` | 中栏：列表、批量操作条、搜索 |
| `62-views.js` | 工作台、待整理、整理中心、集合、收藏、最近访问、调用记录等视图 |
| `64-detail.js` | 右栏记忆详情（属性、证据、版本、AI 辅助、关联对象） |
| `66-editor.js` / `68-quick.js` | 记忆编辑器、快速新增 |
| `70-dialogs.js` | 通用弹窗：建立关联、集合编辑、导入导出、确认框 |
| `72-assist.js` | AI 建议相关展示（归类、找相似、查冲突、上下游） |
| `74-graph.js` | 关系图画布：节点渲染、拖拽、平移缩放、框选、记忆区、布局保存 |
| `76-tidy.js` | 整理中心卡片（重复、候选对象、缺来源、未归类等） |
| `77-knode.js` | 知识对象视图与对话框：四视图、对象详情、新建/合并/建立关系、步骤编辑 |
| `78-settings.js` | DSH 设置页里的知微节区（存储路径、导出导入、模型） |
| `80-panel.js` | 主面板状态机：导航、选中、数据加载、所有操作的手柄（记忆/对象/关系/集合/布局） |
| `90-apply.js` | 向 DSH 注册侧栏入口与设置节区 |

样式全部是 `.zw-` 前缀的 CSS，用 `h('style', null, CSS)` 注入，不依赖外部 CSS 文件，也不污染 DSH 其他界面。

## 三、一次请求怎么走

界面里任何操作都走同一条路：

```
点按钮 → 80-panel.js 的 handle → POST /design-memory/api { action, ...参数 }
      → 40-apply.js 分发 → 30-store.js persist()（串行写锁）
      → applyAction → 具体业务函数（改 state）→ 规范化 → 原子写盘 → 返回新状态
      → 前端 setState，局部重渲染
```

- **读**：`GET /design-memory/api` 直接返回整库状态（记忆、关系、集合、知识对象、布局、视图）；界面一次拿全，后续都在内存里操作，避免零碎请求。
- **写**：所有写操作都经 `persist()`，它持有一把进程内锁：读当前文件 → 应用变更 → 规范化 → 写临时文件 → 原子替换，失败则回滚到内存快照。并发写不会互相覆盖。
- **错误**：业务层用 `httpError(status, code, message)` 抛出，前端统一把 `message` 显示成红条，`code` 用于判断（例如 `protected` 会提示先解除保护）。

## 四、AI 是怎么接进来的

知微不自己起模型服务，分两条路：

1. **对话里的 AI**（推荐）：六个工具暴露给 DSH 的对话模型，由它判断什么时候该 recall、什么时候该 observe。工具返回结构化结果，AI 再解释给用户听。系统提示里注入了一段话，要求 AI 在给建议前先 recall、在得到确认后 observe。
2. **界面里的"AI 建议"**：确定性启发式引擎（`25-assist.js`），不依赖任何模型就能给出标签、领域、相似记忆、候选关系、候选集合。结果标明"仅供参考，不会自动写入"。

如果 DSH 注入了模型运行时（`ctx.inject(['llm'])`），设置页里可以选模型，界面的"AI 分析"按钮会真的调用它；没注入时该按钮退化为启发式结果，不会报错。

## 五、数据存在哪

- 默认：`%USERPROFILE%\.dsh\design-memory\memories.json`
- 可在 DSH 设置页 → 知微 → 存储里改成任意绝对路径（换路径会先做一次导出备份）
- 写入前会在同目录留一份 `.bak`；文件是 UTF-8 JSON，可以直接用编辑器看，也可以整库导出/导入
- 数据版本独立于插件版本：现在文件里写的是 `version: 6`，插件升级时若发现旧版本会自动迁移（见 `DATA-MODEL.md`）

## 六、可预期的边界

- **单机单用户**：没有账号、没有同步、没有并发多端。多人协作不在设计范围内。
- **规模**：4000 条记忆、1200 个知识对象、4000 条关系是硬上限（超出会拒绝写入并提示）。数据层实测 300 对象 / 1000 记忆下各项操作都在预算内（见 `PERF.md`）。
- **AI 不是必需的**：关掉模型，界面与启发式建议照常工作，只是少了自然语言分析。
- **UI 只服务 Web**：客户端模块跑在 DSH 的 Web 界面里，桌面壳与 Web 是同一套。
