# 更新记录

## 2.3.0 — 记忆区：自己画一块区域，框里的记忆自动归属

- **画框即记忆区**：选「圈区」在画布上画一个框，松手后给它起个名字，这块矩形区域就是一块记忆区；框的位置和大小会存进数据（`frame.rect`），不再只是一次性的圈选。
- **框内自动归属**：只要一条记忆的中心点落在框里，它就自动属于这块记忆区；把记忆拖进拖出，归属会跟着更新（拖动后自动保存布局并重算成员）。嵌套的子框里的记忆也算父框的成员。
- **框里可以画框**：记忆区支持嵌套，父框自动包含子框中的记忆，用来搭「项目 → 系统 → 模块」这种层级；查询与召回都会递归展开子框。
- **检索可以指定记忆区**：侧边面板里每块记忆区行上有一个放大镜按钮，「在这块记忆区里找」会把中栏切换成这块记忆区的清单；AI 侧的 `design_memory_search`、`design_memory_recall` 都新增 `frameId` 参数，可以只在指定记忆区（含嵌套子框）里检索与召回。
- **关系图面板新增记忆区列表**：一次列出所有记忆区与成员数，点名称选中该区全部记忆，行上还能改名、删除、「在这块记忆区里找」。
- **右侧详情栏窄宽适配**：详情栏宽度改为 `clamp(272px, 32vw, 372px)`，事实卡改成自适应多列，窄面板（<860px）时详情栏改为浮层而不是把列表挤没；修掉标签/关联/元信息被横向裁切的问题。
- **数据版本仍是 5**：`frames[].rect` 与 `frame-sync` 是新字段/新动作，旧数据可直接读；`layout-save` 之后宿主会按框重算成员。
- 测试：host 74 tests + WORKSPACE 46 checks、渲染 127 checks、契约 7 checks、迁移 16 checks，静态审计干净。

## 2.2.1 — 记忆框变成可连线的节点

- **记忆框也是节点**：框不再只是画布上的一圈虚线，它在关系图里有了自己的节点（虚线胶囊，带成员数与名称）。可以拖到不挡视线的地方，也可以双击改名。
- **框能连线，实现「项目结构路径」**：用「划线」工具从框拖到一条记忆、或从一条记忆拖到框、或框连框，都会照常弹出建关系对话框；关系两端现在允许是框。删框时连带删掉挂在它身上的关系，不留悬空线。
- **点框 = 选中成员**：单击框会选中它框住的所有记忆并弹出批量操作条；双击进改名。
- **修好工具条叠在一起**：计数（`34 / 8`）、提示、过滤面板原来都塞在工具条里，而计数是绝对定位，结果压在按钮上、还飘到左栏那边。现在工具条只装按钮，计数与提示各自回到画布左下 / 右下；画布容器补上定位上下文，不会再越界到导航栏。
- 数据版本仍是 5，`layout` 现在也接受记忆框的坐标，框拖过的位置会被「保存布局」记住。
- 测试：host 74 + WORKSPACE 31（新增框→记忆、记忆→框、框→框、删框清关系、框坐标落盘），渲染断言 117。

## 2.1.0 — AI 长期记忆：自动沉淀、棘轮演进、自动关系网

2.0 让记忆「有结构」，2.1 让记忆「会生长」：AI 可以自动观察、沉淀、订正、建立关系，但重要约定始终由你拍板。

**记忆演进**
- 每条记忆都有版本历史：内容、变更类型（新建/补充/细化/更正/冲突/合并/保护/状态/恢复）、原因、关联证据、来源对话、时间；可查看、可回滚。
- 证据链：记忆可以挂多条证据（用户陈述 / 确认 / 行为推断 / AI 推测 / 临时要求），带来源对话与置信度。
- 棘轮规则：普通补充直接写新版本；有证据的更正留痕；与已确认内容冲突时**不覆盖**，转为「更新提案」等你确认；AI 推测只能作候选。
- 固有约定（protected）最高保护：正文改动一律拒绝（`409 protected`），AI 只能提示矛盾或过时；保护级别与状态彼此独立。
- 提案中心：`proposal-decide` 接受/拒绝，接受才会应用内容并写新版本。

**自动观察**
- 新工具 `design_memory_observe`：输入一段对话或一批结论，自动判断「补证据 / 更新 / 建候选 / 跳过」，并自动推荐关系。
- 界面顶栏 ✨ 打开观察面板，结果按类型分项展示。

**自动关系网**
- 关系新增置信度、来源（AI / 用户）、更新时间；被用户否决的关系记入墓碑，不会无缘无故重建。
- 建记忆、改记忆、合并记忆后自动增量补关系，不做全量重算。

**主动调用**
- 新工具 `design_memory_recall`：按「当前项目已确认约定 → 相关项目记忆 → 全局习惯 → 其他」分层检索，受保护条目明确标注。
- 真实调用写入调用记录，并累加记忆的调用次数与最近调用时间；左栏「调用记录」可查。
- 说明：**没有实现聊天消息的自动注入**（依赖 DSH 会话接口，插件不伪造成接口），目前靠提示词指引 + 检索工具 + 调用日志落地。

**整理中心**
- 一页集中处理：待确认提案、待确认关系、疑似重复（可直接合并）、孤立记忆、待复核。
- 关系图右上角可直达。

**关系图**

- 新增「按项目」筛选。

**界面**

## 2.0.1 — 修复重启后面板 404

**问题**：2.0.0 装好后刷新页面，左侧栏能进「知微」，主区却一直显示 `HTTP 404`。

**原因**：当前 DSH 版本要求每个工具注册时声明 `output: { schema, render }`。知微的四个工具（search / write / suggest / analyze）只声明了入参，`ctx.tools.register` 直接抛错，插件的 `apply` 中途失败——后面的接口路由没注册上，所以前端请求 `/design-memory/api` 拿到的是 DSH 的 404。数据迁移发生在注册工具之前，所以数据本身已经是新结构，只有接口没起来。

**修复**：四个工具统一补上字符串输出声明（`schema: { type: 'string' }` + 文本渲染），与 DSH 现有插件的写法一致。

**新增**：`tests/dsh-contract.mjs` —— 在没有重启 DSH 的情况下复刻 DSH 的注册校验（工具输出声明、schema 白名单键、路由重复、接口可读性），以后改 host 先跑它，能提前抓到「fiber failed」。

**顺手**：`tests/migrate-live.mjs` 在真实数据已被迁移成版本 3 时自动回落到 v1 fixture，避免「备份断言」误报；同时新增一条「真实数据文件可读、记忆条数正确」的检查。

## 2.0.0 — 知微

从「可整理的画布」升级成面向游戏策划的 AI 知识工作台。

**品牌**：插件名从「策划记忆」改为「知微」。内部包名、数据目录与路由保持不变（`@local/design-memory`、`%DSH_HOME%/design-memory`、`/design-memory/api`），已有记忆不受影响。

**数据模型**
- 记忆类型：设计决策 / 设计规则 / 设计假设 / 设计问题 / 设计方案 / 参考案例 / 数值数据 / 复盘结论 / 流程约定（新增第 9 类，承接旧「工作流」记忆）。
- 业务领域：战斗、成长、经济、关卡、活动、UI/UX、商业化、社交、运营、技术约束，可多选，与类型正交。
- 状态：草稿 / 待确认 / 已生效 / 已废弃 / 已归档。
- 来源区分手动 / 对话 / 导入 / AI 整理，并保留来源说明。
- 存储版本升到 3（`projects / entries / relations / collections / views`），写入前自动 `.bak`，原子落盘。

**关系**
- 八种有方向的语义关系：归属于 / 依赖于 / 影响 / 来源于 / 参考 / 冲突 / 替代 / 细化。
- 关系带说明与确认状态（AI 建议 / 用户已确认 / 用户已拒绝）。
- 建立关系必须经过关系对话框（类型 + 说明 + 方向），不再只有拖拽连线。

**主题集合**
- 取代「记忆区」：一条记忆可属于多个集合，支持手动创建、批量加入/移出、改名改简介、合并、拆分。
- AI 聚类建议带名称、简介与归类理由，由用户接受或忽略。

**界面**
- 全新三栏知识工作台：导航栏 + 主内容区 + 详情栏，两栏可折叠，窄屏自适应。
- 概览页：统计、最近记忆、待整理、最近更新、已确认的设计决策、AI 建议。
- 列表支持搜索与项目/类型/领域/状态/标签联合筛选、列表/卡片布局、排序、多选批量操作。
- 关系图重做：分簇自动布局、集合边界与折叠、按类型/关系/领域/集合筛选、搜索定位、按关系类型区分线型与箭头、框选批量操作、保存视图。

**AI 辅助**
- 新增本地分析引擎与 `design_memory_analyze` 工具：整理、找相似、推荐关联、查冲突、上下游、主题总结，全部附推荐理由。
- 快速新增：粘贴原文即可得到标题/摘要/类型/领域/标签/拆分建议，可一键应用，也可直接保存。
- 原子化拆分：一段内容可拆成多条待确认记忆。

**反馈与安全**
- 统一 toast 反馈，AI 分析有进行中/完成态，删除二次确认。
- 删除记忆或集合后可在 toast 里撤销，连同关系与集合归属一起恢复。
- 空状态给出下一步操作，错误有明确文案。

**兼容**
- 1.x 数据自动迁移：`category → type`、`status → active/draft/deprecated`、`links → references 关系`、`regions → 主题集合`；原文与时间戳不变，旧分类/状态保留在 `legacy` 字段。
