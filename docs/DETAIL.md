# 知微 · 详细说明

> 面向游戏策划的 AI 知识工作台。左侧栏进入，三栏工作台里记录、整理、探索你的设计知识。
> 本文对应 2.0.0 版；1.3.0 及更早版本的「策划记忆」数据会自动迁移，见文末。

## 它解决什么

策划的知识散在聊天记录、文档、表格和脑子里：一条数值口径、一次设计评审的结论、一个还没验证的假设、一个被新方案替代的旧规则。时间一长，找不回来，也说不清「这条还生效吗」。

知微把每条知识变成一条**结构化记忆**：有类型、有状态、有来源、有业务领域、有语义关系，可以被 AI 整理、被用户确认，也可以被检索和探索。

## 界面：三栏知识工作台

- **左栏**：项目空间、全部记忆、待整理、主题集合、收藏、最近访问、关系图；底部是保存的图谱视图；最上方是显眼的「新建记忆」入口。默认展开、带文字说明（也可以手动收起成图标条，选择会记住）；导航区独立滚动，项目/视图再多也不会把底部的收起按钮顶出屏幕。
- **右栏**：只在选中一条记忆后才出现；切换左栏视图、换项目、进关系图时自动收起——换了地方就不会还挂着上一条记忆。
- **中栏**：全局搜索 + 筛选条（项目 / 类型 / 领域 / 状态 / 标签）、列表或卡片布局、排序；概览页展示最近记忆、待整理、最近更新、已确认的设计决策与 AI 建议。
- **右栏**：当前记忆的类型与状态、来源、正文、业务领域、所属集合、关联记忆（按关系类型分组并显示确认状态）、AI 辅助面板与改动记录。

两边的栏都可以折叠（详情栏折叠成一个窄条），窗口变窄时自动收起。

## 记忆模型

每条记忆包含：

| 字段 | 说明 |
| --- | --- |
| `title` | 标题，AI 可代拟 |
| `content` | 正文（Markdown 风格：`#` 小标题、`-` 列表、`>` 引用、`` ` `` 行内代码） |
| `summary` | 一句话摘要，未填时自动从正文推导 |
| `type` | 设计决策 / 设计规则 / 设计假设 / 设计问题 / 设计方案 / 参考案例 / 数值数据 / 复盘结论 / 流程约定 |
| `domains` | 业务领域，可多选：战斗、成长、经济、关卡、活动、UI/UX、商业化、社交、运营、技术约束 |
| `tags` | 自由标签 |
| `status` | 草稿 / 待确认 / 已生效 / 已废弃 / 已归档 |
| `source` | 来源类型与说明：手动 / 对话 / 导入 / AI 整理 |
| `projectId` | 所属项目空间 |
| `facts` | 要点（名称 = 值），适合放数值口径 |
| `pinned` / `favorite` | 置顶 / 收藏 |
| `createdAt` / `updatedAt` | 时间戳 |
| `history` | 改动记录（最近 30 条） |
| `relatedCollectionIds` | 所属主题集合（由集合推导） |

`type` 与 `domains` 是**两个维度**：类型回答「这条知识是什么」，领域回答「它属于哪块业务」。一条战斗系统的数值配置，类型是「数值数据」，领域是「战斗 + 成长」。

> 流程约定（`process`）是 2.0.0 新增的第九种类型：旧数据里大量「工作流」类记忆原先无类可归，强行塞进其他类型会失真，因此保留为独立类型。

## 状态与确认

状态不是装饰，它决定你把这条知识当什么用：

- **草稿**：随手记下的想法。
- **待确认**：AI 整理过但还没被人确认的结果，默认落在这一档。
- **已生效**：确认过的规则/决策。
- **已废弃**：被替代的旧结论，保留可追溯。
- **已归档**：不再活跃，但留档备查。

AI 不会把「设计假设」自动升格成「设计规则」：任何建议都要人点一下才变成已生效。

## 关系：有类型、有方向、有确认状态

关系不再是一条无意义的连线，而是明确的语义：

| 类型 | 含义 |
| --- | --- |
| `belongs_to` | 归属于 |
| `depends_on` | 依赖于 |
| `affects` | 影响 |
| `derived_from` | 来源于 |
| `references` | 参考 |
| `conflicts_with` | 冲突 |
| `supersedes` | 替代 |
| `refines` | 细化 |

每条关系记录 `sourceMemoryId → targetMemoryId`、类型、说明、状态（AI 建议 / 用户已确认 / 用户已拒绝）、创建者与时间。

**怎么建关系**：详情栏「建立关联」，或在关系图里用「划线」工具从一个节点拖到另一个节点，都会弹出关系对话框——选类型、写可选说明、看清方向，再确认。AI 推荐的关系以「AI 建议」状态出现，接受后变成「用户已确认」。

## 主题集合：替代「手动画区」

集合是一条条记忆的**主题分组**，一条记忆可以同时属于多个集合：

- 手动创建：名称、简介、项目、颜色。
- 批量加入 / 移出成员；改名、改简介；合并两个集合、从集合里拆出新集合。
- 「加入集合」弹窗（批量加、单条记忆的集合编辑）顶部可直接输入名字新建集合并自动勾上，回车即建，不用退出弹窗。
- AI 聚类建议：根据领域与标签把记忆分团，给出**名称 + 简介 + 归类理由**，由用户接受或忽略。
- 集合页可以一键「生成总结」：主题概述、要点、分布与成员列表。

关系图里仍然可以画框圈选一组记忆——但框选只是**视觉辅助**，真正的归属由集合决定。框选后会给出「创建主题集合」「批量改状态」「加入已有集合」等操作。

## AI 辅助

分析引擎在本地运行（无外部模型依赖），结果是**可解释的启发式建议**，全部标注理由：

- **整理这条**：拟标题、提摘要、判类型（附理由）、识别领域（附理由）、抽标签，并给原子化拆分建议。
- **找相似**：按共同标签、领域、正文重合度打分，给出相似度与理由。
- **推荐关联**：推断应建立的关系类型（替代 / 冲突 / 来源 / 细化 / 依赖 / 影响 / 参考）与置信度。
- **查冲突**：数值不一致或主题高度重叠时提示检查——但**不武断判定冲突**，因为旧方案不一定错，可能只是被新方案替代。
- **上下游**：沿关系双向展开两层，看这条记忆影响谁、依赖谁。
- **主题总结**：对集合或整个项目生成概述与要点。

新增记录的流程是：原始内容 → 理解 → 原子化拆分 → 分类建议 → 领域识别 → 关系推荐 → 用户确认 → 正式入库。快速新增面板只要粘贴一段话就能拿到全部建议，也可以直接「只保存」。

## 自动沉淀与棘轮式演进

知微的记忆不是「一次写入就不再变化」的静态条目，而是有版本、有证据、有保护级别的长期资产。

**自动沉淀**（`memory-observe`）：把一段对话或一批结论交给 `design_memory_observe` 工具，host 会逐条判断它与已有记忆的关系：

- 已有记忆能覆盖这条信息 → 只追加一条证据，并刷新调用时间（`reinforced`）。
- 新信息是对已有记忆的补充/细化/更正 → 走演进流程，必要时生成提案（`updated` / `proposed`）。
- 完全新的知识点 → 建一条「待确认」的记忆，并自动推荐关系（`created` + `relations`）。
- 一次性、临时性、明显不属于长期知识的内容 → 跳过（`skipped`）。

界面上，顶栏 ✨ 按钮可以直接粘贴一段对话跑一次观察，结果按「新建 / 更新 / 提案 / 强化 / 跳过 / 关系」分项列出。

**棘轮规则**（不默认覆盖）：

| 情况 | 处理 |
| --- | --- |
| 普通记忆的补充、细化 | 直接写入新版本，旧版本完整保留 |
| 已有证据的更正 | 写入新版本，版本记录写清原因 |
| 与已确认内容冲突 | 不覆盖，生成「更新提案」，等你 accept / reject |
| 固有约定（protected）的正文改动 | 一律拒绝（`409 protected`），只能由你显式确认或解除保护 |
| AI 推测 | 只能作为候选记忆或提案，不能直接改已生效内容 |

**版本与证据**：每条记忆有 `versions[]`（版本号、内容、变更类型、原因、关联证据、来源对话、时间）和 `evidence[]`（证据类型、内容、来源对话、置信度）。详情页可以看版本历史、一键回滚到旧版本、补一条证据。

**保护级别**：`普通 / 已确认 / 固有约定`。固有约定是最高保护，AI 只能提示「可能过时」或展示矛盾证据，不能自己改。保护级别和状态是两个维度：固有约定可以被你废弃，但不会被系统自动改。

**生命周期字段**：置信度、重要程度、调用次数、最近调用时间、证据数、过期时间。重要记忆不会因为最近没被调用就被删除——调用频率只影响推荐排序。

## 主动调用与调用记录

新对话需要相关记忆时，智能体用 `design_memory_recall` 按任务检索：它按「当前项目已确认的约定 → 相关项目记忆 → 全局习惯 → 其他」分层返回，受保护条目会明确标注；同一任务下不会塞满无关内容。

每次真实调用都会写进调用记录（任务、取用条目、结果、时间）并累加记忆的调用次数，左栏「调用记录」能查到 AI 到底在什么时候取用过哪条记忆——**不做伪造的「自动注入」**：注入依赖 DSH 的会话接口，当前以提示词指引 + 真实检索工具 + 调用日志来实现，文档如实说明。

## 整理中心

「整理中心」把需要人拍板的事集中到一页：待确认提案、待确认关系、疑似重复（可直接合并）、孤立记忆（没关系的节点）、待复核条目。所有动作都是真实的库操作，不是视图层过滤。

## 关系图的语义增强

- 关系带置信度、来源（AI 发现 / 用户手动）和确认状态；低置信建议显示为虚线，被否决的关系不会在没有新理由时重建。
- 选中节点时高亮它的**上游**（指向它的关系）与**下游**（它指出的关系），箭头方向即语义方向。
- 按项目、类型、关系类型、领域、集合过滤；图例里区分建议中 / 已确认 / 已否决的连线。
- 关系图右上角可直接进入整理中心。
## 关系图：知识探索工具

- 自动布局（按集合/领域成簇），节点可拖拽——拖动只改变显示位置，不改变数据。
- 集合显示为带名称的边界框，可折叠成单个簇节点，也可以展开。
- 按类型、关系类型、领域、集合筛选；搜索定位、点击开详情。
- 八种关系类型用不同颜色与线型区分，建议关系为虚线，选中/悬停时显示关系名称。
- 框选多个节点 → 批量操作条（加入集合、改状态、清除）。
- 保存当前视图（筛选、折叠状态、工具状态）到左栏，随时恢复。

## 操作反馈与撤销

创建、编辑、状态变更、建关系、集合操作、批量操作都有 toast 反馈；AI 分析有进行中与完成态；删除需要二次点击确认。**删除记忆或集合后，toast 里提供「撤销」**，撤销会把记忆连同它的关系、集合归属一起恢复（数据库层面是真实的 `entry-restore` / `collection-restore`，不是前端假恢复）。

## AI 工具（给对话里的智能体用）

| 工具 | 用途 |
| --- | --- |
| `design_memory_search` | 按 id / 关键词 / 类型 / 领域 / 状态 / 项目 / 集合 / 收藏检索，列表带 id，取单条返回全文 |
| `design_memory_write` | 记忆、关系、集合、项目、视图的增删改（含 `entry-restore` 撤销、`entry-collections` 调整归属） |
| `design_memory_suggest` | 整理建议、聚类建议、关联建议 |
| `design_memory_analyze` | 整理 / 找相似 / 推荐关联 / 冲突检查 / 上下游 / 主题总结，返回中文可读报告 |
| `design_memory_observe` | 自动观察：把一段对话/一批结论沉淀成记忆、补证据或生成更新提案 |
| `design_memory_recall` | 按任务分层检索记忆，并记录这次真实调用 |

## 数据与备份

- 存储：`%DSH_HOME%/design-memory/memories.json`（默认 `C:\Users\<你>\.dsh\design-memory\`），版本 4。
- 每次写入前把上一版复制为 `memories.json.bak`；写入走临时文件 + 原子改名；解析失败时文件改名 `memories.json.corrupt-<时间戳>` 并重置，不静默丢数据。
- 备份：直接复制整个 `design-memory` 目录即可。

## 从 1.x 迁移

首次启动会就地迁移，并在写回前留一份 `.bak`：

- `category` → `type`：`system → rule`、`numbers → metric`、`workflow → process`、`other → reference`；原始分类保留在 `legacy.category`。
- `status` → `active`（原 `confirmed`）/ `draft` / `deprecated`；原始状态保留在 `legacy.status`。
- `links[]` → 关系：`references`，状态「用户已确认」，原说明作为关系说明。
- `regions[]` → 主题集合：状态「已确认」，来源「手动」，成员照搬。
- 标题、正文、标签、要点、时间戳、置顶、来源全部原样保留；旧记忆正文不会被截断或覆盖。

迁移后可核对记忆条数与关系条数与迁移前一致（`tests/migrate-live.mjs` 就是以真实数据做这项校验的）。

## 限制

- 分析引擎是规则化的启发式，不做语义向量检索；数据量大时相似度按标签/领域/正文重合度近似。
- 关系图针对几百条记忆的量级设计；更多时建议用集合折叠与筛选控制密度。
- 记忆冲突检测只给「可能冲突」的线索，最终判断始终由用户做出。
- 暂无多用户协作与云同步；数据在本机。
