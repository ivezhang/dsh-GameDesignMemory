# 知微 · 详细说明

> 面向游戏策划的 AI 知识工作台。左侧栏进入，三栏工作台里记录、整理、探索你的设计知识。
> 本文对应 2.0.0 版；1.3.0 及更早版本的「策划记忆」数据会自动迁移，见文末。

## 它解决什么

策划的知识散在聊天记录、文档、表格和脑子里：一条数值口径、一次设计评审的结论、一个还没验证的假设、一个被新方案替代的旧规则。时间一长，找不回来，也说不清「这条还生效吗」。

知微把每条知识变成一条**结构化记忆**：有类型、有状态、有来源、有业务领域、有语义关系，可以被 AI 整理、被用户确认，也可以被检索和探索。

## 界面：三栏知识工作台

- **左栏**：项目空间、全部记忆、待整理、主题集合、收藏、最近访问、关系图；底部是保存的图谱视图；最上方是显眼的「新建记忆」入口。默认展开、带文字说明（也可以手动收起成图标条，选择会记住）；导航区独立滚动，项目/视图再多也不会把底部的收起按钮顶出屏幕。
- **右栏**：只在选中一条记忆后才出现；切换左栏视图、换项目、进关系图时自动收起——换了地方就不会还挂着上一条记忆。
- **中栏**：全局搜索 + 筛选条（项目 / 类型 / 领域 / 状态 / 标签）、列表或卡片布局、排序；概览页展示最近记忆、待整理、最近更新、已确认的设计决策与 AI 建议。
- **右栏**：当前记忆的类型与状态、来源、正文、业务领域、所属集合、关联记忆（按关系类型分组并显示确认状态）、AI 辅助面板与改动记录。

两边的栏都可以折叠（详情栏折叠成一个窄条），窗口变窄时自动收起。

## 记忆模型

每条记忆包含：

| 字段 | 说明 |
| --- | --- |
| `title` | 标题，AI 可代拟 |
| `content` | 正文（Markdown 风格：`#` 小标题、`-` 列表、`>` 引用、`` ` `` 行内代码） |
| `summary` | 一句话摘要，未填时自动从正文推导 |
| `type` | 设计决策 / 设计规则 / 设计假设 / 设计问题 / 设计方案 / 参考案例 / 数值数据 / 复盘结论 / 流程约定 |
| `domains` | 业务领域，可多选：战斗、成长、经济、关卡、活动、UI/UX、商业化、社交、运营、技术约束 |
| `tags` | 自由标签 |
| `status` | 草稿 / 待确认 / 已生效 / 已废弃 / 已归档 |
| `source` | 来源类型与说明：手动 / 对话 / 导入 / AI 整理 |
| `projectId` | 所属项目空间 |
| `facts` | 要点（名称 = 值），适合放数值口径 |
| `pinned` / `favorite` | 置顶 / 收藏 |
| `createdAt` / `updatedAt` | 时间戳 |
| `history` | 改动记录（最近 30 条） |
| `relatedCollectionIds` | 所属主题集合（由集合推导） |

`type` 与 `domains` 是**两个维度**：类型回答「这条知识是什么」，领域回答「它属于哪块业务」。一条战斗系统的数值配置，类型是「数值数据」，领域是「战斗 + 成长」。

> 流程约定（`process`）是 2.0.0 新增的第九种类型：旧数据里大量「工作流」类记忆原先无类可归，强行塞进其他类型会失真，因此保留为独立类型。

## 状态与确认

状态不是装饰，它决定你把这条知识当什么用：

- **草稿**：随手记下的想法。
- **待确认**：AI 整理过但还没被人确认的结果，默认落在这一档。
- **已生效**：确认过的规则/决策。
- **已废弃**：被替代的旧结论，保留可追溯。
- **已归档**：不再活跃，但留档备查。

AI 不会把「设计假设」自动升格成「设计规则」：任何建议都要人点一下才变成已生效。

## 关系：有类型、有方向、有确认状态

关系不再是一条无意义的连线，而是明确的语义：

| 类型 | 含义 |
| --- | --- |
| `belongs_to` | 归属于 |
| `depends_on` | 依赖于 |
| `affects` | 影响 |
| `derived_from` | 来源于 |
| `references` | 参考 |
| `conflicts_with` | 冲突 |
| `supersedes` | 替代 |
| `refines` | 细化 |

每条关系记录 `sourceMemoryId → targetMemoryId`、类型、说明、状态（AI 建议 / 用户已确认 / 用户已拒绝）、创建者与时间。

**怎么建关系**：详情栏「建立关联」，或在关系图里用「划线」工具从一个节点拖到另一个节点，都会弹出关系对话框——选类型、写可选说明、看清方向，再确认。AI 推荐的关系以「AI 建议」状态出现，接受后变成「用户已确认」。

## 主题集合：替代「手动画区」

集合是一条条记忆的**主题分组**，一条记忆可以同时属于多个集合：

- 手动创建：名称、简介、项目、颜色。
- 批量加入 / 移出成员；改名、改简介；合并两个集合、从集合里拆出新集合。
- 「加入集合」弹窗（批量加、单条记忆的集合编辑）顶部可直接输入名字新建集合并自动勾上，回车即建，不用退出弹窗。
- AI 聚类建议：根据领域与标签把记忆分团，给出**名称 + 简介 + 归类理由**，由用户接受或忽略。
- 集合页可以一键「生成总结」：主题概述、要点、分布与成员列表。
- 「管理集合」一栏把维护动作集中起来：改名 / 改描述 / 改颜色 / 改项目、勾选同步成员（只增删变化的部分）、合并到另一个集合、删除集合。

关系图里仍然可以画框圈选一组记忆——但框选只是**视觉辅助**，真正的归属由集合决定。框选后会给出「创建主题集合」「批量改状态」「加入已有集合」等操作。

## AI 辅助

分析引擎在本地运行（无外部模型依赖），结果是**可解释的启发式建议**，全部标注理由：

- **整理这条**：拟标题、提摘要、判类型（附理由）、识别领域（附理由）、抽标签，并给原子化拆分建议。
- **找相似**：按共同标签、领域、正文重合度打分，给出相似度与理由。
- **推荐关联**：推断应建立的关系类型（替代 / 冲突 / 来源 / 细化 / 依赖 / 影响 / 参考）与置信度。
- **查冲突**：数值不一致或主题高度重叠时提示检查——但**不武断判定冲突**，因为旧方案不一定错，可能只是被新方案替代。
- **上下游**：沿关系双向展开两层，看这条记忆影响谁、依赖谁。
- **主题总结**：对集合或整个项目生成概述与要点。

新增记录的流程是：原始内容 → 理解 → 原子化拆分 → 分类建议 → 领域识别 → 关系推荐 → 用户确认 → 正式入库。快速新增面板只要粘贴一段话就能拿到全部建议，也可以直接「只保存」。

## 自动沉淀与棘轮式演进

知微的记忆不是「一次写入就不再变化」的静态条目，而是有版本、有证据、有保护级别的长期资产。

**自动沉淀**（`memory-observe`）：把一段对话或一批结论交给 `design_memory_observe` 工具，host 会逐条判断它与已有记忆的关系：

- 已有记忆能覆盖这条信息 → 只追加一条证据，并刷新调用时间（`reinforced`）。
- 新信息是对已有记忆的补充/细化/更正 → 走演进流程，必要时生成提案（`updated` / `proposed`）。
- 完全新的知识点 → 建一条「待确认」的记忆，并自动推荐关系（`created` + `relations`）。
- 一次性、临时性、明显不属于长期知识的内容 → 跳过（`skipped`）。

界面上，顶栏 ✨ 按钮可以直接粘贴一段对话跑一次观察，结果按「新建 / 更新 / 提案 / 强化 / 跳过 / 关系」分项列出。

**棘轮规则**（不默认覆盖）：

| 情况 | 处理 |
| --- | --- |
| 普通记忆的补充、细化 | 直接写入新版本，旧版本完整保留 |
| 已有证据的更正 | 写入新版本，版本记录写清原因 |
| 与已确认内容冲突 | 不覆盖，生成「更新提案」，等你 accept / reject |
| 固有约定（protected）的正文改动 | 一律拒绝（`409 protected`），只能由你显式确认或解除保护 |
| AI 推测 | 只能作为候选记忆或提案，不能直接改已生效内容 |

**版本与证据**：每条记忆有 `versions[]`（版本号、内容、变更类型、原因、关联证据、来源对话、时间）和 `evidence[]`（证据类型、内容、来源对话、置信度）。详情页可以看版本历史、一键回滚到旧版本、补一条证据。

**保护级别**：`普通 / 已确认 / 固有约定`。固有约定是最高保护，AI 只能提示「可能过时」或展示矛盾证据，不能自己改。保护级别和状态是两个维度：固有约定可以被你废弃，但不会被系统自动改。

**生命周期字段**：置信度、重要程度、调用次数、最近调用时间、证据数、过期时间。重要记忆不会因为最近没被调用就被删除——调用频率只影响推荐排序。

## 主动调用与调用记录

新对话需要相关记忆时，智能体用 `design_memory_recall` 按任务检索：它按「当前项目已确认的约定 → 相关项目记忆 → 全局习惯 → 其他」分层返回，受保护条目会明确标注；同一任务下不会塞满无关内容。

每次真实调用都会写进调用记录（任务、取用条目、命中的知识对象、结果、时间）并累加记忆的调用次数，左栏「调用记录」能查到 AI 到底在什么时候取用过哪条记忆——**不做伪造的「自动注入」**：注入依赖 DSH 的会话接口，当前以提示词指引 + 真实检索工具 + 调用日志来实现，文档如实说明。

## 整理中心

「整理中心」把需要人拍板的事集中到一页：待确认提案、待确认关系、疑似重复（可直接合并）、孤立记忆（没关系的节点）、待复核条目。所有动作都是真实的库操作，不是视图层过滤。

## 关系图的语义增强

- 关系带置信度、来源（AI 发现 / 用户手动）和确认状态；低置信建议显示为虚线，被否决的关系不会在没有新理由时重建。
- 选中节点时高亮它的**上游**（指向它的关系）与**下游**（它指出的关系），箭头方向即语义方向。
- 按项目、类型、关系类型、领域、集合过滤；图例里区分建议中 / 已确认 / 已否决的连线。
- 关系图右上角可直接进入整理中心。
## 知识网络：对象与记忆双层

2.5 起，知微在记忆之上加了一层**知识对象**（KnowledgeNode），关系图默认画对象、记忆按需展开。

- **对象类型**：项目、系统、子系统、业务概念（怪物 / 装备 / 技能 / 副本…）、工作流程、用户偏好、设计原则、设计方法。对象带类型专属属性（怪物写阵营与定位，流程写步骤，偏好写倾向与避免），还有别名、父级、适用范围与状态（候选 / 有效 / 已归档 / 已合并）。
- **记忆与对象是多对多**：一条记忆能挂到多个对象上，一个对象能聚合多条记忆；记忆详情里显示所属对象并可跳转，对象详情里可关联 / 解除关联记忆（解除只断开关系，记忆还在）。
- **四个视图共用一套数据**：项目视图看结构，工作视图看流程与约定，偏好视图看长期习惯，全局视图跨维度看联系；切换视图只改筛选，不复制节点。
- **画布交互**：对象是双圈 + 类型单字，记忆是实心点；`+N` 徽章折叠 / 展开子树；单击选中、双击聚焦上下游、Ctrl 或 Shift 点击多选、Space 加拖动平移、Shift 加拖动空白框选、滚轮以指针为中心缩放、点空白取消选择。
- **建立关系**：工具栏「建立关系」→ 选目标（对象或记忆）→ 选 28 种关系之一（层级 / 业务 / 流程 / 偏好原则 / 知识五组）→ 实时看到自然语言预览并可按「反向」→ 保存。自反、类型不适用、层级成环、重复关系都会被拦下并说明原因。
- **合并对象**：详情里点「合并」，对比字段后保留主对象，关系与关联记忆迁过去并去重，来源对象标记为已合并（保留历史与指向）。
- **自动观察产出候选**：AI 观察出与已有记忆相关的对象时，只会写候选并给创建建议，正式对象由你或明确的确认产生。

## 关系图：知识探索工具

- 自动布局（按集合/领域成簇），节点可拖拽——拖动只改变显示位置，不改变数据。
- 集合显示为带名称的边界框，可折叠成单个簇节点，也可以展开。
- 按类型、关系类型、领域、集合筛选；搜索定位、点击开详情。
- 八种关系类型用不同颜色与线型区分，建议关系为虚线，选中/悬停时显示关系名称。
- 框选多个节点 → 批量操作条（加入集合、改状态、清除）。
- 点空的深色背景（不拖动）= 退出选择并收起右侧详情栏；拖动背景仍是平移画布。
- 保存当前视图（筛选、折叠状态、工具状态）到左栏，随时恢复。

## 项目空间

左栏的「项目空间」按项目组织记忆：项目行右键可以改名或删除（删除时把该项目里的记忆与集合迁到第一个项目，记忆本身不丢），行可以拖动排序——拖动时只改本地顺序，松手才写库。分组标题右侧的「+」直接新建项目，填写名称与说明即可，新建后立刻成为当前筛选范围。

## 关系图：记忆区与布局

- **记忆区 = 你自己画的框**（2.3）：选工具条上的「记忆区」在画布上画一个矩形，松手后起名，这块区域就成了一条数据（`frame.rect` 存位置与大小），不再只是一次性的圈选。「圈选」只负责选中一组节点，不会再顺手建区。
- **画好的区可以改**（2.3.1）：按住框拖动整块区域，四角把手缩放；双击框顶的名字改名；选中后按 Delete / Backspace 删除。框换了位置，框里的记忆按新位置重算归属。
- **框里画进去的，就属于它**：一条记忆的节点中心落在框的范围内，就自动成为这块记忆区的成员；把节点拖进拖出，归属跟着变（拖动后自动保存布局并重算成员）。框里还可以再画框，父框自动包含子框里的记忆——所以能把「项目 → 系统 → 模块」一层层圈出来。
- **和主题集合是两回事**：集合按领域/标签自动聚类（实线轮廓），记忆区是你手动画的（虚线轮廓，位置本身就是含义）；两者可以重叠，互不改变记忆归属。
- **框是节点，可以连线**（2.2.1）：每个框在画布上还有一个自己的节点（虚线胶囊 + 成员数），可以拖动、双击改名。用「划线」工具从框拖到一条记忆、从一条记忆拖到框、或框连框，会照常弹出「建立关系」对话框——关系两端允许是框。这样就可以把「星云勘测」这一组记忆收进一个框，再把这个框连到「战斗系统」「活动」等别的节点上，形成项目结构路径。
- **侧边面板管理记忆区**：一次列出所有记忆区与成员数；点名称选中该区全部记忆，行上可以改名、删除（记忆本身保留），也可以「在这块记忆区里找」——中栏会切成这块记忆区的清单。
- **检索可以指定记忆区**：AI 侧的 `design_memory_search` 与 `design_memory_recall` 都接受 `frameId`，只在该记忆区（含嵌套子框）里检索或召回；不确定归属时先用工具查一次。
- 单击框会选中它框住的所有记忆并弹出批量操作条；删框会连带删掉挂在框上的关系，不会留下悬空连线。框的坐标随「保存布局」一起保存。
- **保存布局**：手动拖好的节点位置可以保存到数据里（`layout.positions`），下次打开关系图按保存位置还原，再跑一次局部松弛。不想保留时清掉布局即可回到自动布局。
- **画布控件不重叠**（2.2.1）：工具条只装按钮（放不下会换行），节点/连线计数在画布左下，临时提示在右下；画布容器自带定位上下文，不会越界压到左栏。

## 设置（在 DSH 设置页里）

插件不再自带设置弹窗：打开 DSH 的设置，左栏「知微」一节里有三块内容：

- 存储位置：显示当前 `memories.json` 路径，可切换到任意目录或 `.json` 文件；切换前在旧位置留一份 `.before-switch` 备份，随时切回。
- 导出：把记忆、关系、集合、记忆框与布局导出成 JSON，用于备份或换机。
- 导入：合并（只补充缺失条目，按 id 去重）或覆盖（整体替换当前库）。
- 整理用的模型：从宿主当前可用的服务商与模型里选一个并启用（通过依赖注入拿到 DSH 的模型运行时，不再读不存在的 ctx.llm）。AI 整理会优先走模型；模型不可用或返回不可解析内容时，自动回退本地启发式整理并在结果里说明，所以没有模型也能用。

设置保存在与记忆库同目录的 `config.json`（`storageFile` + `model`），不影响记忆数据本身。
## 召回路径

召回不是把整库倒出来，而是走一条能解释的链路：任务词命中知识对象 → 对象的关联记忆 → （必要时）顺着一条关系再取一跳。
每次调用都会把这条链路记下来（起点是知识对象，最多 6 跳），调用记录里显示成「对象 → 关系 → 记忆」，方便事后判断「为什么当时调用了它」。

## 流程步骤的拖动排序

流程对象（工作流程）的步骤在编辑框里可以拖动排序：每个步骤左侧有拖拽把手，拖到目标行时该行出现虚线落位提示，松手即换序；上移 / 下移按钮保留给键盘操作。顺序在保存时按当前排列写入，数据里就是步骤数组的顺序。

## 批量操作

多选（列表勾选，或关系图里 Shift 框选 / Ctrl 点击）之后，底部出现批量条：

- **加入集合**：勾选集合，也可以当场新建；
- **设为有效**：批量把状态改成「已生效」；
- **归档**：批量改成「已归档」（不删内容）；
- **加标签**：输入一个标签，选中的记忆都会加上（已有同名标签不重复加，其它标签不动）；
- **删除**：二次确认后删除，可从提示里的「撤销」恢复。

## 搜索

搜索框同时覆盖记忆（标题 / 正文 / 标签）、知识对象（标题 / 描述 / 别名 / 标签）、主题集合与项目，结果分组显示：

- 知识对象：点击切到知识网络并打开对象详情；
- 主题集合：点击直达集合页；
- 项目：点击按该项目过滤列表。

## 跨项目隔离

调用 design_memory_recall 时如果带上 projectId，只有本项目的记忆和全局记忆（scope=global）参与排序，别的项目的记忆即使词面命中也不会返回；知识对象同样按项目收口（全局对象仍参与）。

不传 projectId 时保持原来的行为：全部记忆参与，按「本项目有效约定 → 本项目记忆 → 全局 / 习惯 → 其他」分层展示，层级写在每条结果的 tier 里。

## 键盘快捷键

| 快捷键 | 作用 |
| --- | --- |
| Ctrl / Cmd + K | 聚焦顶栏搜索框（任意视图） |
| Enter | 在搜索框里打开第一条结果 |
| Esc | 关闭最上层弹窗或菜单；没有弹窗时取消当前选择 |
| Space + 拖动 | 在关系图里平移画布 |
| Shift + 拖动空白 | 框选节点 |
| Ctrl / Cmd + 点击 | 多选切换 |
| Delete / Backspace | 删除选中的记忆区；选中知识对象时询问归档还是彻底删除 |

输入框里打字时画布快捷键不生效，避免误触。

## 从视图隐藏

- 知识对象详情头部的眼睛按钮可以把对象「从视图隐藏」：画布上不再显示它，但记忆、关系、集合、记忆区归属都不受影响。
- 关系图右侧的过滤面板会显示「已隐藏 N」，点「恢复全部隐藏节点」一次性恢复。
- 隐藏状态与画布坐标都存在布局里（纯视觉状态），和业务数据分开；保存布局时不会互相覆盖。

## 关系类型的语义分组

新建关系时，关系类型不是一长串平铺的 chip，而是按语义分组：

- 层级：包含 / 属于 / 是……的一部分
- 业务：出现在 / 使用 / 掉落 / 需要 / 由……制作 / 影响 / 依赖 / 与……平衡
- 流程：遵循 / 先于 / 下一步 / 触发 / 产出 / 是……的例外
- 偏好与原则：偏好 / 避免 / 适用于 / 指导 / 约束
- 知识：关联于 / 来源于 / 参考 / 冲突 / 替代 / 细化

分组只影响展示，不影响数据；同一对端点之间仍然只存一条同类型关系。

## 知识对象的版本历史

知识对象（项目 / 系统 / 概念 / 流程 / 偏好 / 原则 / 方法）的每次改名、改描述、改类型、改状态都会追加一版：记录时间、变更类型、原因。对象详情里的「历史版本」列出每一版，除当前版外都能「回到这一版」——回滚会恢复标题、描述与类型，并把回滚本身也记一版，历史只增不减。版本上限 40 条。

这和记忆的版本是两套：记忆的版本记正文、证据与提案；对象的版本记它的名字与描述。两边都保留来源，回滚不会删掉中间过程。

## 操作反馈与撤销

创建、编辑、状态变更、建关系、集合操作、批量操作都有 toast 反馈；AI 分析有进行中与完成态；删除需要二次点击确认。**删除记忆或集合后，toast 里提供「撤销」**，撤销会把记忆连同它的关系、集合归属一起恢复（数据库层面是真实的 `entry-restore` / `collection-restore`，不是前端假恢复）。新建关系后也可以撤销（删掉刚建的那条），删除关系后可以撤销（按原端点与类型重建），给集合添加成员后可以撤销（移除刚加进来的成员）——撤销只回退对应那一次操作。

## AI 工具（给对话里的智能体用）

| 工具 | 用途 |
| --- | --- |
| `design_memory_search` | 按 id / 关键词 / 类型 / 领域 / 状态 / 项目 / 集合 / 收藏检索，列表带 id，取单条返回全文 |
| `design_memory_write` | 记忆、关系、集合、项目、视图的增删改（含 `entry-restore` 撤销、`entry-collections` 调整归属） |
| `design_memory_suggest` | 整理建议、聚类建议、关联建议 |
| `design_memory_analyze` | 整理 / 找相似 / 推荐关联 / 冲突检查 / 上下游 / 主题总结，返回中文可读报告 |
| `design_memory_observe` | 自动观察：把一段对话/一批结论沉淀成记忆、补证据或生成更新提案 |
| `design_memory_recall` | 按任务分层检索记忆，并记录这次真实调用 |

## 数据与备份

- 存储：`%DSH_HOME%/design-memory/memories.json`（默认 `C:\Users\<你>\.dsh\design-memory\`），版本 4。
- 每次写入前把上一版复制为 `memories.json.bak`；写入走临时文件 + 原子改名；解析失败时文件改名 `memories.json.corrupt-<时间戳>` 并重置，不静默丢数据。
- 备份：直接复制整个 `design-memory` 目录即可。

## 从 1.x 迁移

首次启动会就地迁移，并在写回前留一份 `.bak`：

- `category` → `type`：`system → rule`、`numbers → metric`、`workflow → process`、`other → reference`；原始分类保留在 `legacy.category`。
- `status` → `active`（原 `confirmed`）/ `draft` / `deprecated`；原始状态保留在 `legacy.status`。
- `links[]` → 关系：`references`，状态「用户已确认」，原说明作为关系说明。
- `regions[]` → 主题集合：状态「已确认」，来源「手动」，成员照搬。
- 标题、正文、标签、要点、时间戳、置顶、来源全部原样保留；旧记忆正文不会被截断或覆盖。

迁移后可核对记忆条数与关系条数与迁移前一致（`tests/migrate-live.mjs` 就是以真实数据做这项校验的）。

## 限制

- 分析引擎是规则化的启发式，不做语义向量检索；数据量大时相似度按标签/领域/正文重合度近似。
- 关系图针对几百条记忆的量级设计；更多时建议用集合折叠与筛选控制密度。
- 记忆冲突检测只给「可能冲突」的线索，最终判断始终由用户做出。
- 暂无多用户协作与云同步；数据在本机。
