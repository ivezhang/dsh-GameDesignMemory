# 知微 · 功能总览（v2.3.2）

> 面向评审：这份文档说明「现在能做什么、怎么用、边界在哪」。内部包名仍是 `@local/design-memory`，数据目录仍是 `%USERPROFILE%\.dsh\design-memory`，只有用户可见的名字叫「知微」。

---

## 一、定位

知微是 DeepSeek Harness 里的一个**长期记忆与知识管理插件**，给游戏策划用。它想解决的问题不是「存更多笔记」，而是：

- 你和我讨论过的东西，**下次还能被找回来**；
- 会被**持续订正**，而不是每次重新记一遍；
- 重要的约定**不会被 AI 擅自改掉**；
- 记忆之间的**关系自动长出来**，而不是靠人一根根画线；
- 你要能**一眼看懂**一个项目的设计结构，并直接在上面做管理决策。

一句话：**AI 负责记、连、整理、提议；人负责确认、驳回、决定。**

## 二、界面结构：三栏知识工作台

```
┌────────────┬──────────────────────────────┬──────────────────┐
│ 左栏导航    │ 中栏（列表 / 工作台 / 关系图）  │ 右栏详情          │
└────────────┴──────────────────────────────┴──────────────────┘
```

**左栏**（默认展开、可收起、导航区独立滚动，记忆多了也不挤）

| 入口 | 作用 |
| --- | --- |
| 新建记忆 | 快速录入（AI 自动起标题、判类型、提领域与标签） |
| 工作台 | 统计、最近新增、待确认、AI 建议、调用记录 |
| 全部记忆 | 全量清单 + 搜索 + 多维筛选 |
| 待整理 | 草稿 / 待确认 / 待复核的记忆 |
| 整理中心 | 提案、待确认关系、疑似重复、孤立记忆 |
| 主题集合 | 人为或 AI 聚类出的主题分组 |
| 收藏 / 最近访问 | 常用入口 |
| 调用记录 | 每次「按任务召回」的真实记录 |
| 项目空间 | 多项目隔离，支持右键改名/删除、拖动排序、新建 |
| 关系图 | 知识探索与管理主界面 |

**中栏**：顶部是搜索 + 类型/领域/状态/标签筛选 + 排序 + 列表/卡片切换；不同入口切换不同视图（工作台、清单、集合详情、整理中心、关系图）。
**右栏**：只在选中一条记忆后出现，换视图/换项目/进关系图会自动收起——不占常驻空间。

## 三、记忆数据模型

### 3.1 记忆（Memory）

| 维度 | 取值 |
| --- | --- |
| 类型（13） | 设计决策、设计规则、设计假设、设计问题、设计方案、参考案例、数值数据、复盘结论、流程约定、用户习惯、通用约定、项目背景、临时事项 |
| 业务领域（10，可多选） | 战斗、成长、经济、关卡、活动、界面交互、商业化、社交、运营、技术 |
| 状态（6） | 草稿、待确认、待复核、已生效、已废弃、已归档 |
| 保护级别（3） | 普通、已确认、固有约定（锁定） |
| 作用域（2） | 全局、项目 |
| 来源（4） | 手动、对话、导入、AI 整理 |
| 其他 | 标题、正文（Markdown）、摘要、标签、要点、置信度、重要程度、使用次数、最近调用时间、过期时间、被替代指向 |

**状态与保护级别是两个独立维度**：一条「固有约定」可以被用户废弃，但不能被系统自动改。

### 3.2 关系（Relation）

8 种，**有方向**：归属于、依赖于、影响、来源于、参考、冲突、替代、细化。

每条关系带：置信度、依据、来源（AI 发现 / 用户手动）、状态（AI 建议 / 用户已确认 / 用户已拒绝）、时间。
**用户否决过的关系不会被无理由重建**（否决会被记住）。

### 3.3 演进记录

| 结构 | 内容 |
| --- | --- |
| 版本（MemoryVersion） | 每次内容变化存一版：改了什么类型（新建/补充/细化/纠正/冲突/合并/保护/状态/回滚）、原因、证据、时间、谁改的 |
| 证据（MemoryEvidence） | 原始来源：来源对话、来源消息、证据原文、证据类型（用户陈述/确认/行为推断/推测/临时） |
| 更新提案（MemoryUpdateProposal） | 不能直接改的时候（固有约定、冲突、已确认决策）生成提案：旧内容、建议内容、原因、依据，等用户采纳/拒绝 |
| 调用记录（Recall） | 每次按任务召回：任务描述、取用了哪些记忆、结果（采用/忽略/冲突） |

### 3.4 组织

- **项目**：项目空间，记忆与集合都归属到项目；删项目会把内容迁到第一个项目，不丢数据。
- **主题集合（Collection）**：人为建或 AI 聚类建议；一条记忆可属于多个集合；支持改名/改描述/增删成员/合并/拆分。
- **记忆区（Memory area）**：**你自己在关系图上画的框**，是空间容器而不是标签。框里的记忆自动归属，框可以嵌套（框里画框），组件可被连接，检索与召回都能指定「只在某块记忆区里找」。

## 四、核心能力

### 4.1 快速新增 + AI 整理

输入一段话保存，系统会即时给出建议：

- 标题（取第一句核心）、摘要；
- 类型 + 判断理由；
- 领域 + 判断理由；
- 标签（结合历史语料抽取）；
- 归属项目；
- **原子拆分建议**：一段话里含多个知识点时，给出拆成多条的建议，可逐条「拆出这条」；
- 相关记忆与可关联的关系建议。

建议一律以「待确认」供给，用户点采纳才写入；也可以「跳过 AI 只保存」。

### 4.2 自动观察与棘轮式演进

这是 2.1 之后的重点能力。给它一段对话或笔记，它会：

1. 抽取候选记忆（区分用户明确事实 / 多次确认的约定 / 行为推断的习惯 / AI 推测 / 临时要求）；
2. 与已有记忆比对（共同标签、领域、数值、语义重合度）；
3. 决定处理方式：
   - 已有记忆覆盖 → 只补证据（reinforced）；
   - 新的细节 → 补充/细化（追加版本）；
   - 与已有说法冲突 → 生成**更新提案**，不静默改；
   - 没有对应记忆 → 建「待确认」候选；
4. 自动建立关系（带置信度，可后续确认/否决）；
5. 全程留下版本与证据。

**硬规则**：固有约定（protected）只能由用户改；任何内容更新都会留下前后版本与依据。

### 4.3 AI 辅助（不做聊天窗，做动作按钮）

选中一条记忆，右栏「AI 辅助」提供 5 个动作：

| 动作 | 产出 |
| --- | --- |
| 整理这条 | 建议的标题/类型/领域/标签/摘要 + 拆分建议 + 可建立的关系；确认后回写 |
| 找相似 | 相似度排序的候选（附相似理由） |
| 推荐关联 | 可建立的关系，一键采纳 |
| 查冲突 | 数值不一致 / 主题重叠的候选，给四种处置：以新替旧、都适用、保留冲突、不是冲突 |
| 上下游 | 沿关系双向 BFS 的依赖与影响范围 |

集合层还有「生成总结」：总览、要点、主题、成员。

**能力边界（如实说明）**：插件本身不带大模型时用**确定性启发式引擎**（关键词打分、标签语料匹配、中文 n-gram 抽词、共同标签/同领域推关系、贪心聚类），结果可靠可解释但不等于语义理解。在设置里指定「整理用的模型」后，`整理这条` 会先调用该模型产出结构化建议，失败自动回落启发式，界面会标明来源（模型 / 本地）。

### 4.4 主动调用（真实检索，不伪造）

- 提供 `design_memory_recall(task)` 工具：按任务检索并分层给结果——① 当前项目已生效/已确认的约定（含固有约定，明确标注）→ ② 当前项目相关记忆 → ③ 全局用户习惯 → ④ 其他；历史方案默认不当成当前有效规则；冲突优先提示。
- 每次调用都写「调用记录」，用户能在「调用记录」里看到最近被召回的内容。
- 宿主里注册了一段系统提示，告诉对话中的 AI：什么时候该召回、什么时候该沉淀、哪些内容不能替用户确认。
- **没有做**：把记忆自动注入到每条对话（技术上需要伪造消息注入，宁可不做也不假装做到了）。

### 4.5 关系图：探索 + 管理

- **自动布局**：力导向 + 按集合分簇，减少重叠与交叉；节点拖动后可「保存布局」，下次还原。
- **节点可辨**：颜色区分类型，状态（草稿/废弃/归档）有视觉区分，尺寸随关联数变化；建议关系用虚线弱连接表示。
- **筛选**：按项目、类型、关系类型、领域、集合、记忆区过滤；只显示待确认的弱连接。
- **搜索定位**：面板里搜标题/正文/标签，点结果即在图上聚焦。
- **多选与批量**：框选多个节点 → 批量加入集合、改状态、清除；图上也能直接处理 AI 建议（确认/否决关系）。
- **上下游高亮**：选中一个节点，高亮它的上游（被依赖）与下游（影响）。
- **记忆区**：工具条「记忆区」直接画框 → 命名 → 框内节点自动归属；框可拖动整块、四角缩放、双击改名、Delete 删除；框里可再画框；框本身也是节点，可以连到别的记忆或框，形成「项目 → 系统 → 模块 → 规则」的结构路径。
- **主题视图**：把当前视角（筛选 + 布局）保存成命名视图，左侧栏一键恢复。

### 4.6 整理中心（治理）

一次性列出需要人决策的事：

- **待确认提案**（AI 想改固有约定 / 冲突待判）；
- **待确认关系**（AI 发现但没被确认的关系，可批量确认/否决）；
- **疑似重复**（可合并：关系重指向、集合成员合并、证据合并、版本留档）；
- **孤立记忆**（没有任何关系、也没进集合的记忆，提示补关系或归区）。

### 4.7 设置中心

- **存储位置切换**：把记忆库换到别的磁盘/目录，切换前自动留 `.before-switch` 备份；
- **导出 / 导入**：导出整库 JSON（含记忆、关系、集合、提案、调用记录、记忆区、布局）；导入支持合并（按 id 去重）与覆盖；
- **整理用的模型**：选择 provider 与模型，或「只用本地整理」；
- 显示当前存储路径与模型状态。

## 六、数据安全

- 存储：`%USERPROFILE%\.dsh\design-memory\memories.json`（或设置里切换的位置），`config.json` 存存储路径与模型选择。
- 每次保存：先写 `.bak` 备份 → 写临时文件 → 原子改名；解析失败会把坏文件备份成 `.corrupt-<时间戳>` 再重建，不覆盖你的数据。
- 迁移：v1 → v2 → v3 → v4 → v5 逐级自动迁移，迁移前留备份，迁移后核对数量。
- 删除有「撤销」：删记忆、删集合、删记忆区都会给撤销入口（恢复关系与集合成员）。
- 现有 34 条线上记忆已完整迁移，未丢字段。

## 八、已知边界 / 未做

1. **不做自动注入**：记忆不会自动出现在每条对话里，需要 AI 主动调用 `design_memory_recall`（这是有意的坦白，不是漏做）。
2. **本地引擎不是大模型**：不配置模型时，判断基于关键词与统计；配了模型才会走语义整理。
3. **撤销只覆盖删除**：移动、缩放、改名没有独立撤销栈。
4. **框与框的连线端点**落在框的把手节点上，没有精确吸附到矩形边线。
5. **布局不跨设备同步语义**：记忆区归属依赖画布坐标，如果只导入数据没导入布局，老框会退回「按成员列表」。
6. **关系图节点上限**：默认单项目几百节点可用，数千节点会明显变慢（未做 WebGL / 虚拟化）。
7. **知识问答、决策链路可视化**只预留了数据结构（类型、关系、版本），没有独立界面。
