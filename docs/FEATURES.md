# 知微 · 功能总览（v2.8.0）

> 面向评审：这份文档说明「现在能做什么、怎么用、边界在哪」。内部包名仍是 `@local/design-memory`，数据目录仍是 `%USERPROFILE%\.dsh\design-memory`，只有用户可见的名字叫「知微」。

---

## 一、定位

知微是 DeepSeek Harness 里的一个**长期记忆与知识管理系统**，给游戏策划用。它想解决的问题不是「存更多笔记」，而是：

- 你和我讨论过的东西，**下次还能被找回来**；
- 会被**持续订正**，而不是每次重新记一遍；
- 重要的约定**不会被 AI 擅自改掉**；
- 记忆之间的**关系自动长出来**，而不是靠人一根根画线；
- 你要能**一眼看懂**一个项目的设计结构，并直接在上面做管理决策。

从 2.5 起它有两层：**记忆（Memory）**负责「说过什么」，**知识对象（KnowledgeNode）**负责「项目里有什么」——系统、子系统、业务对象、流程、偏好、原则、方法。两者多对多，对象之间的语义关系构成项目结构骨架。

一句话：**AI 负责记、连、整理、提议；人负责确认、驳回、决定。**

## 二、界面结构：三栏知识工作台

```
┌────────────┬──────────────────────────────┬──────────────────┐
│ 左栏导航    │ 中栏（列表 / 工作台 / 知识网络） │ 右栏详情          │
└────────────┴──────────────────────────────┴──────────────────┘
```

**左栏**（默认展开、可收起、导航区独立滚动，记忆多了也不挤）

| 入口 | 作用 |
| --- | --- |
| 新建记忆 | 快速录入（AI 自动起标题、判类型、提领域与标签） |
| 工作台 | 统计、最近新增、待确认、AI 建议、调用记录 |
| 全部记忆 | 全量清单 + 搜索 + 多维筛选（搜索同时命中知识对象） |
| 待整理 | 草稿 / 待确认 / 待复核的记忆 |
| 整理中心 | 提案、待确认关系、疑似重复、孤立记忆、候选对象、重复对象 |
| 知识网络 | **核心新页**：知识对象图谱，四个视图（项目结构 / 工作流程 / 用户偏好 / 全局知识） |
| 主题集合 | 人为或 AI 聚类出的主题分组（含集合管理/合并/删除） |
| 收藏 / 最近访问 | 常用入口 |
| 调用记录 | 每次「按任务召回」的真实记录，含命中对象与召回路径 |
| 项目空间 | 多项目隔离，支持右键改名/删除、拖动排序、新建 |
| 关系图 | 记忆视角的关系图（划区、连线、布局） |

**中栏**：顶部是搜索 + 类型/领域/状态/标签筛选 + 排序 + 列表/卡片切换；知识网络页顶部换成四个视图页签 + 对象/记忆计数 + 「新建知识对象」。
**右栏**：只在选中一条记忆或一个知识对象后出现，换视图/换项目/进关系图会自动收起——不占常驻空间。

## 三、数据模型

### 3.1 记忆（Memory）

| 维度 | 取值 |
| --- | --- |
| 类型（13） | 设计决策、设计规则、设计假设、设计问题、设计方案、参考案例、数值数据、复盘结论、流程约定、用户习惯、通用约定、项目背景、临时事项 |
| 业务领域（10，可多选） | 战斗、成长、经济、关卡、活动、界面交互、商业化、社交、运营、技术 |
| 状态（6） | 草稿、待确认、待复核、已生效、已废弃、已归档 |
| 保护级别（3） | 普通、已确认、固有约定（锁定） |
| 作用域（2） | 全局、项目 |
| 来源（4） | 手动、对话、导入、AI 整理 |
| 其他 | 标题、正文（Markdown）、摘要、标签、要点、置信度、重要程度、使用次数、最近调用时间、过期时间、被替代指向、所属知识对象 |

**状态与保护级别是两个独立维度**：一条「固有约定」可以被用户废弃，但不能被系统自动改。

### 3.2 知识对象（KnowledgeNode）

| 维度 | 取值 |
| --- | --- |
| 类型（8） | 项目、系统、子系统、业务对象、工作流程、用户偏好、设计原则、设计方法 |
| 状态（4） | 候选、有效、已归档、已合并 |
| 属性 | 键值对（怪物写类型/阵营/定位，流程写触发/输入输出，偏好写类别/倾向/避免） |
| 流程步骤 | 仅工作流程：有序步骤（标题、说明、关联记忆），可上移/下移 |
| 其他 | 标题、描述、作用域、项目、父级对象、子对象、标签、别名、关联记忆、版本历史、合并指向 |

**一条记忆可以挂到多个对象；一个对象可以有多个父级之外的关联**——四类知识（项目结构 / 工作流程 / 用户偏好 / 设计知识）共用同一套对象与记忆底座，不各建一套库。

### 3.3 关系（Relation）

28 种，**都有方向与语义**，分五组：

| 组 | 类型 |
| --- | --- |
| 层级 | 包含、属于、部分属于 |
| 业务 | 出现在、使用、掉落、需要、由…制作、影响、依赖、平衡于 |
| 流程 | 接续、先于、下一步、触发、产出、例外 |
| 偏好原则 | 偏好、避免、适用于、指导、约束 |
| 通用 | 相关、来源于、参考、冲突、替代、细化 |

两端可以是知识对象或记忆（`sourceType/sourceId → targetType/targetId`）。每条关系带置信度、依据、来源（AI 发现 / 用户手动）、状态（AI 建议 / 用户已确认 / 用户已拒绝）、时间。
创建时会拦截：自反、类型不适用（如「掉落」只能对业务对象）、层级成环、重复（对称关系反向也算重复）。预览会给一句人话，例如「哥布林 → 掉落 → 铁矿石」。
**用户否决过的关系不会被无理由重建**（否决会被记住）。

### 3.4 演进记录

| 结构 | 内容 |
| --- | --- |
| 记忆版本（MemoryVersion） | 每次内容变化存一版：改了什么类型（新建/补充/细化/纠正/冲突/合并/保护/状态/回滚）、原因、证据、时间、谁改的 |
| 对象版本（NodeVersion） | 知识对象也有版本历史：改名、改描述、改类型、归档、回滚都会留一版，可在详情里回滚到任意一版 |
| 证据（MemoryEvidence） | 原始来源：来源对话、来源消息、证据原文、证据类型（用户陈述/确认/行为推断/推测/临时） |
| 更新提案（MemoryUpdateProposal） | 不能直接改的时候（固有约定、冲突、已确认决策）生成提案：旧内容、建议内容、原因、依据，等用户采纳/拒绝 |
| 调用记录（Recall） | 每次按任务召回：任务描述、命中知识对象、取用了哪些记忆、召回路径（对象 → 关系 → 记忆）、结果（采用/忽略/冲突） |

### 3.5 组织

- **项目**：项目空间，记忆、对象与集合都归属到项目；删项目会把内容迁到第一个项目，不丢数据。
- **主题集合（Collection）**：人为建或 AI 聚类建议；一条记忆或对象可属于多个集合；支持改名/改描述/增删成员/合并/拆分/删除。
- **记忆区（Memory area）**：**你自己在关系图上画的框**，是空间容器而不是标签。框里的记忆自动归属，框可以嵌套（框里画框），框本身也是节点可被连接，检索与召回都能指定「只在某块记忆区里找」。

## 四、核心能力

### 4.1 快速新增 + AI 整理

输入一段话保存，系统会即时给出建议：标题、摘要、类型 + 理由、领域 + 理由、标签、归属项目、**原子拆分建议**（一段话含多个知识点时可逐条「拆出这条」）、相关记忆与关系建议。
建议一律以「待确认」供给，用户点采纳才写入；也可以「跳过 AI 只保存」。

### 4.2 自动观察与棘轮式演进

给它一段对话或笔记，它会：抽取候选记忆（区分用户明确事实 / 多次确认的约定 / 行为推断的习惯 / AI 推测 / 临时要求）→ 与已有记忆比对 → 分情况处理（覆盖则只补证据、新细节追加版本、冲突生成提案、无对应则建「待确认」候选）→ 自动建立带置信度的关系 → 全程留版本与证据。
2.5 起它还会先看**知识对象**：能匹配上现有对象就优先把记忆挂到对象下；匹配不上就给出「候选知识对象」建议，而不是直接造一堆低质量节点。

**硬规则**：固有约定（protected）只能由用户改；任何内容更新都会留下前后版本与依据。

### 4.3 AI 辅助（不做聊天窗，做动作按钮）

选中一条记忆，右栏「AI 辅助」提供 5 个动作：整理这条 / 找相似 / 推荐关联 / 查冲突（四种处置）/ 上下游（双向 BFS）。
集合层有「生成总结」：总览、要点、主题、成员。

**能力边界（如实说明）**：插件本身不带大模型时用**确定性启发式引擎**（关键词打分、标签语料匹配、中文 n-gram 抽词、共同标签/同领域推关系、贪心聚类），结果可靠可解释但不等于语义理解。在 DSH 设置里指定「整理用的模型」后，`整理这条` 会先调用该模型产出结构化建议，失败自动回落启发式，界面会标明来源（模型 / 本地）。

### 4.4 知识网络（2.5 新增，四视图）

- **四个视图共用一套数据**：项目结构（项目/系统/子系统/业务对象）、工作流程（流程 + 步骤）、用户偏好（习惯、约定、偏好）、全局知识（原则、方法、通用参考）。切视图不复制节点、不改数据。
- **对象与记忆是两层**：默认画对象节点（双圈 + 单字类型标），记忆按需展开；对象与记忆双向可达（对象详情看关联记忆，记忆详情看所属对象）。
- **创建/编辑对象**：类型 → 名称与描述 → 适用范围 → 父级；重名/相似会先提示「可能已存在」，可选「用这个 / 继续创建 / 取消」，不会静默合并。编辑有编辑态，保存前不覆盖原数据；改类型若影响已有关系会先列出受影响关系并要求确认；改名全视图同步。
- **合并重复对象**：独立对话框，对比两侧名称/类型/状态/记忆数/描述，保留主对象 ID、迁移关系与关联记忆并去重、来源对象标记「已合并」并指向主对象。
- **关联记忆**：右栏可「关联已有记忆」或「新建并关联」；解除关联只解除关系，不删记忆。
- **从视图隐藏**：对象详情里的眼睛按钮把节点从画布藏起来（数据不删），图右上角可恢复全部。
- **对象版本历史**：详情里能看到每一版并回滚。
- **画布交互**：单击选中 → 右栏详情；双击聚焦上下游；拖节点移动；拖空白平移；滚轮以指针为中心缩放；Shift 拖空白框选；Ctrl/Cmd 点击多选；`+N` 徽章折叠/展开子对象；Esc 取消选择，Delete 打开删除/归档确认（不会直接删）。
- **布局**：自动布局 + 适应画布 + 保存布局；拖动只改位置，不改业务归属。

### 4.5 主动调用（真实检索，不伪造）

- `design_memory_recall(task)`：**先识别知识对象，再检索记忆**——命中对象后把它的关联记忆加权重，再顺一层关系扩大召回；分层给结果（① 当前项目已生效且已确认的约定，含固有约定并明确标注 → ② 当前项目相关记忆 → ③ 全局用户习惯 → ④ 其他）。
- 每次调用写「调用记录」：任务、命中对象、取用记忆、**召回路径**（对象 → 关系 → 记忆）、结果。
- 宿主里注册了一段系统提示，告诉对话中的 AI：什么时候该召回、什么时候该沉淀、哪些内容不能替用户确认。
- **没有做**：把记忆自动注入到每条对话（技术上需要伪造消息注入，宁可不做也不假装做到了）。

### 4.6 关系图（记忆视角）

- 自动布局 + 按集合分簇；节点拖动后自动保存或手动保存布局，下次还原。
- 节点可辨：颜色区分类型，状态有视觉区分，尺寸随关联数变化；建议关系用虚线弱连接。
- 筛选：按项目、类型、关系类型、领域、集合、记忆区；只显示待确认的弱连接。
- 搜索定位（同时搜记忆、知识对象、集合与项目，结果分组）、多选与批量（加入集合、设为有效、归档、加标签、删除，删除二次确认）、上下游高亮、主题视图保存。
- **记忆区工具**：直接画框 → 命名 → 框内节点自动归属；框可拖动整块、四角缩放、双击改名、Delete 删除；框里可再画框；框可连线到别的记忆或框，形成「项目 → 系统 → 模块 → 规则」的结构路径。

### 4.7 整理中心（治理）

一次性列出需要人决策的事：待确认提案、待确认关系（可批量确认/否决）、疑似重复记忆、孤立记忆、**候选知识对象**（可单条或全部确认）、**疑似重复的知识对象**（一键进入合并）。每条都带原因，不靠猜。

### 4.8 设置（在 DSH 设置页里）

- **存储位置切换**：把记忆库换到别的磁盘/目录，切换前自动留 `.before-switch` 备份；
- **导出 / 导入**：导出整库 JSON（记忆、关系、集合、提案、调用记录、记忆区、布局、知识对象与对象版本）；导入支持合并（按 id 去重）与覆盖；
- **整理用的模型**：选择 provider 与模型，或「只用本地整理」——通过依赖注入拿到 DSH 的模型运行时，选完立刻生效。

## 六、数据安全

- 存储：`%USERPROFILE%\.dsh\design-memory\memories.json`（或设置里切换的位置），`config.json` 存存储路径与模型选择。
- 每次保存：先写 `.bak` 备份 → 写临时文件 → 原子改名；解析失败会把坏文件备份成 `.corrupt-<时间戳>` 再重建，不覆盖你的数据。
- 迁移：v1 → v2 → v3 → v4 → v5 → v6 逐级自动迁移，迁移前留备份，迁移后核对数量。
- **真实迁移报告**（`docs/MIGRATION-REPORT.md`）：拿线上库副本跑 v5→v6，记忆 34→34、关系 8→8、集合 1→1、记忆区 1→1、项目 1→1，知识对象 1（项目自动节点，没有凭空造对象），34/34 条记忆都有版本历史与来源证据，关系全部写成双端点；迁移后在真实数据上冒烟 8/8 通过。
- 删除有「撤销」：删记忆、删集合、删记忆区、删/加关系、给集合加成员都有撤销入口；知识对象默认走「归档」，彻底删除需要二次确认。
- 关联与删除分得很清：解除对象与记忆的关联**不会**删记忆。

## 八、已知边界 / 未做

1. **不做自动注入**：记忆不会自动出现在每条对话里，需要 AI 主动调用 `design_memory_recall`（有意为之，不假装做到）。
2. **本地引擎不是大模型**：不配置模型时，判断基于关键词与统计；配了模型才走语义整理。
3. **撤销不覆盖全部操作**：删除、关系、集合成员可撤销；移动节点、缩放记忆区、改名没有独立撤销栈。
4. **记忆区与对象是两套组织**：记忆区按画布坐标归属，知识对象按父级/关系归属，两者都保留但不会自动互相转换。
5. **对象重复率靠提醒**：创建时做相似检测并要求确认，不做全库自动合并。
6. **关系图节点上限**：单项目几百节点可用，数千节点会明显变慢（未做 WebGL / 虚拟化）。
7. **知识问答、结构缺口分析**只预留了数据结构（对象、关系、版本、召回路径），没有独立界面。
8. **框与框连线的端点**落在记忆区的把手节点上，没有精确吸附到矩形边线。
