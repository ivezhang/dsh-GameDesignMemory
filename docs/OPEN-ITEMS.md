## 二、功能上还没做的

### 4. AI 聚类仍走启发式

"建议集合"与"找相似"用的是确定性的词频/标签重合算法（`25-assist.js`），不是语义向量。好处是不需要模型、结果可解释、离线可用；代价是同义词识别弱（"掉落表"与"drop table"不认为相关）。

- 现状：DSH 注入模型时，"AI 分析"按钮会真的调模型做归纳，但集合聚类本身没接模型。
- 接下来：把候选集合的生成改成"启发式召回候选 → 模型只说哪几条该归一起"，避免全库喂给模型。

### 5. 跨对话流程补全只做到"合并步骤"

2.6.5 已经能把第二次观察里的新步骤并进同一个流程对象。但还没做的是：**识别"这两次说的是同一条流程"的语义判断**目前靠标题相同或步骤重合 ≥2，措辞差别大时会另建一个对象，需要人工合并。2.6.7 把「步骤重合」这件事也用到了整理中心的判重上（共享 ≥2 个同名步骤会被列为疑似重复），但仍是字符串完全相同才算同名。

- 接下来：合并时给出"看起来是同一流程"的候选清单，让用户一键合并，而不是静默按标题判。

### 6. 关系图超过 120 节点只有"展开全部"的限制提示

画布超过 120 个节点时点"展开全部"会提示先筛选，但没有更细的聚合策略（比如按记忆区折叠成一个大节点）。上限 1200 对象时画布会很挤。

### 7. 导入只支持整库

2.6.8 之后可以**按项目导出**（项目右键 → 导出这个项目），但导入仍然只能 merge / replace 整库。没有"只导入某几个集合"。多个人各管一个项目时，合起来要靠 merge 整库后人工清理重复。另：2.6.8 之前导出的整库 JSON 里没有知识对象，旧备份导入后对象层是空的。

### 8. 撤销栈只保留最近 5 步，且不跨重启

2.6.9 加了全局撤销（Ctrl / Cmd + Z，栈深 5）：记忆 / 对象 / 关系 / 集合 / 项目 / 记忆框 / 导入都能整步退回。仍然做不到的：
- 只留最近 5 步，更早的改动找不回来；
- 撤销栈在内存里，重启 DSH 即清空；
- 拖动节点产生的位置保存不进栈（会连续触发），布局拖乱还是得靠保存的视图。

## 四、不算缺陷但要知道的边界

- 单机单用户，没有多端同步与并发写保护（同一文件被两个 DSH 实例同时写会互相覆盖，`persist()` 的锁只在单进程内有效）。
- 记忆与对象的上限是硬限制（4000 / 1200），超了直接拒绝写入并提示，不会静默丢弃。
- 英文界面只翻译了插件框架层（`locale/en.json`），知微自身的界面文案以中文为主，未做完整英文覆盖。
- 数据文件是单个 JSON，整库读进内存；靠上限控制在几十 MB 量级，超过这个量级要换存储（例如拆文件或 SQLite）。
