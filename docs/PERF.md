# 数据层性能实测

> 由 tests/perf.mjs 在临时 DSH_HOME 里生成 301 个知识对象、1000 条记忆、300 条关系的库，然后逐个量接口耗时。只覆盖数据层与接口层，**不代表浏览器里的帧率与绘制耗时**。

## 结果

| 场景 | 耗时 | 预算 | 结果 |
| --- | --- | --- | --- |
| 首次读取整库（加载 + 规范化） | 74.9 ms | 800 ms | 达标 |
| 再次读取整库 | 23.8 ms | 200 ms | 达标 |
| 搜索「掉落」 | 2.5 ms | 150 ms | 达标 |
| 按任务召回（10 条） | 91.1 ms | 250 ms | 达标 |
| 整理中心报告 | 103.0 ms | 300 ms | 达标 |
| 按记忆区检索（无框，走全库） | 0.7 ms | 200 ms | 达标 |
| 保存 300 个节点的布局 | 55.3 ms | 400 ms | 达标 |

合计 7 / 7 达标。

## 怎么读这组数字

- 预算按「一个人在界面上操作不会觉得卡」定的：一次读整库、一次搜索、一次召回都在 200–300ms 以内。
- 首次读取包含读取文件、迁移与规范化，所以最慢；之后每次请求都会重新读盘（当前实现不缓存），所以「再次读取」的数字是常态成本。
- 节点拖动是 700ms 防抖后一次性保存，不是每帧存盘，所以拖动过程中不会触发这里的写盘。
- 真正的浏览器绘制耗时要在 DevTools Performance 里看，见 docs/WALKTHROUGH.md 的走查项。
