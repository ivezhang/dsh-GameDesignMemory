# 策划记忆 v1.3.0 升级说明

一句话：关系网从「只能看的连线图」升级成「能直接改的神经网络」——可以在图上**划线建立关联**，也可以**拖框把一堆记忆圈成一个记忆区**。

- 上一版：v1.2.0
- 这一版：v1.3.0
- 数据格式：`version` 1 → 2（新增 `regions`，旧文件自动兼容）
- 升级动作：换掉 `index.js` / `client.js`，重启或刷新 DSH 面板即可，**不需要迁移数据**

---

## 一、加了三个能力

### 1. 划线建立关联

以前要建立关联，得先选中一条记忆、滚到详情页底部、在「关联记忆」里选目标、再点添加。现在直接在图上画：

- 工具栏中间切到 **划线**，从一个节点拖到另一个节点，松手就连上了。
- 拖动时有一条虚线跟着光标，光标下的目标节点会高亮，告诉你「会连到这里」。
- 按住 `Shift` 拖节点，任何工具状态下都能临时划线，不用来回切工具。
- 拖到空白处、或者连到自己身上，会弹一句瞬时提示，不会产生脏数据。

写进去的和详情页添加的关联是同一条数据，两种入口可以混用。

### 2. 画框圈记忆区

新概念「记忆区」：把一堆有关系的记忆圈在一起，像白板上的框。

- 工具栏切到 **圈区**，在空白处拖一个框，松手即建区；框里没有节点时不会建，只提示一下。
- 区在图上画成一圈**带颜色的光晕**，把区里的节点包起来，旁边带「区名 · 条数」标签。
- 关系网右上角会出现 **记忆区** 面板（有区时才出现）：点一行聚焦这个区，其他节点和连线变淡；点色块换颜色（六色轮转）；点名字直接改名；垃圾桶点两下删除整个区。
- **一条记忆最多属于一个区**：把它画进新区，会自动从旧区移走。这样每个区都是一份干净的清单，不会出现一条记忆同时在三个框里的糊涂账。
- 删除区只删分区，记忆本身还在；区里空了，区自动消失。
- 列表视图里，属于某个区的记忆，详情顶部会显示一个区名标签，不用切回关系网就知道它归属哪。
- 重新排版时按区聚类：同一个区的节点会被拉到一起，一眼能看出结构。

### 3. 神经网络视觉

整块图重画了一遍，目标是「像神经元网络，而不是流程框图」：

| 元素 | 之前 | 现在 |
|---|---|---|
| 节点 | 实心圆点 | 三层结构：外发光光晕（带呼吸动画）+ 环 + 核心点，颜色仍是分类色 |
| 连线 | 直线 + 小箭头 | 二次贝塞尔曲线，带轻微弧度，避免多条线叠在一起看不出方向 |
| 信号 | 无 | 沿连线流动的短脉冲，看起来像神经信号在传 |
| 背景 | 网格 | 暗角光晕 + 点阵底纹 |
| 记忆区 | 无 | 凸包光晕（单点画圆、两点画胶囊、多点画平滑闭合曲线），区色半透明填充 |
| 悬停 / 选中 | 变色 | 目标节点描边高亮、选中节点多一圈外环、无关节点自动变淡 |

浅色和深色各有一套色值，深色下不会出现刺眼的白光圈。所有颜色都走插件自己的 `--dm-*` 语义变量，跟随 DSH 主题切换。

## 二、上手（30 秒）

| 想做的事 | 怎么做 |
|---|---|
| 给两条记忆连一条线 | 切到「划线」→ 从 A 拖到 B |
| 临时连一条线，不切工具 | 按住 `Shift` 拖 A 到 B |
| 把一堆记忆圈起来 | 切到「圈区」→ 在空白处拖一个框 |
| 只看某个区 | 右上角记忆区面板点那一行（再点取消） |
| 给区换个颜色 | 点区前面的小色块 |
| 给区改名 | 点区名 → 直接输入 → 回车（`Esc` 取消） |
| 删掉一个区（保留记忆） | 垃圾桶点两下 |
| 回到普通操作 | 切回「选择」 |

工具按钮在工具栏中间，顺序是 **选择 / 划线 / 圈区**，当前生效的那个会高亮；图区左下角还有一行随工具变化的操作提示。

## 三、数据格式变化

文件位置不变：`%DSH_HOME%\design-memory\memories.json`。

```json
{
  "version": 2,
  "entries": [ /* 与 v1.2.0 完全一致 */ ],
  "regions": [
    {
      "id": "reg_mabc123_4f2a19",
      "name": "战令与付费点",
      "color": "violet",
      "note": "圈区笔记（可选）",
      "memberIds": ["mem_mabc001_aa11bb", "mem_mabc002_cc33dd"]
    }
  ]
}
```

- 只有 `version` 和 `regions` 是新增的，`entries` 结构没有任何变化。
- `color` 只能是 `violet / blue / teal / amber / rose / lime`，异常值会回落到调色板首色。
- 一条记忆只出现在一个 `regions[].memberIds` 里，host 写入时会自动做互斥清理。
- 上限：最多 40 个区，每个区最多 400 条成员，区名 60 字。

**兼容性：**

- 旧文件（`version: 1`）直接能读：`regions` 按空数组处理，第一次写入时自动升到 `2`。
- 不需要迁移脚本，不需要手动改 JSON。
- 如果回滚到 v1.2.0，多出来的 `regions` 字段会被旧版忽略，记忆条目不受影响（只是分区信息暂时看不到）。
- 写前备份 `memories.json.bak` 的机制没变；读取失败仍然改名成 `memories.json.corrupt-<时间戳>`。

## 四、AI 侧的变化

`design_memory_write` 多了两个动作，参数照旧走同一个工具：

| 动作 | 关键参数 | 作用 |
|---|---|---|
| `region-save` | `regionId`（改已有区时传）、`name`、`color`、`memberIds`、`note` | 新建或修改记忆区；不传 `memberIds` 表示保留原有成员 |
| `region-delete` | `regionId` | 删除记忆区，区里的记忆保留 |

`design_memory_search` 的列表和详情会带上所属记忆区，AI 查结论时能看到「这条属于哪个区」。

可以直接这样说：

```text
把「战令奖励」和「付费点设计」这两条连起来，说明写「战令是主要付费入口」。
把战令相关的这几条记忆圈成一个叫「战令体系」的区，用紫色。
把「战令体系」这个区改名叫「赛季与战令」。
```

## 五、已知限制

- 记忆区是**单层分区**：一条记忆只属于一个区，不支持区里再套区，也没有子图折叠。
- 框选按节点中心点判断，节点被画得很大、框很小时可能漏掉边缘节点，画大一点就好。
- 关系网在宽面板下体验最好；面板很窄时工具栏会自动换行，记忆区面板宽度会压到 54%。
- 条目上千后布局计算会变慢（当前按数百条量级优化），届时建议用「只看这一条」或按区聚焦。

## 七、怎么验证这版是好的

改完后跑过的检查：

1. `node --check index.js` / `node --check client.js`：语法通过。
2. 渲染冒烟测试（假 React + 假 DOM 跑真实组件树）：41 项通过，覆盖列表、状态切换、关系网节点数、自动关联开关、工具栏、抽屉、以及**划线建关联**（断言发出 `action: 'link'` 的请求并带上目标 id）、**框选建区**（断言发出 `action: 'region-save'` 且成员数正确）与区光晕 / 区面板 / 区标签的渲染。
3. i18n 与 CSS 审计：中英文 key 集合一致（136 : 136），无新增未定义类名，无新增未使用类名（少量历史欠账维持原状）。

手动验收建议看四处：划线时虚线跟手、圈区后光晕包住节点、右上角区面板改名换色生效、列表详情顶部出现区名标签。
