# 从 2.0.x 升级到 2.1.0

## 升级步骤

1. 把仓库更新到 `v2.1.0`（或复制新的 `index.js` / `client.js` / `locale` / `docs` 到插件目录）。
2. **完全退出并重启 DSH**。host 与前端都变了：只刷新页面会出现新前端配旧接口。
3. 重启后左侧栏进「知微」，确认能正常加载（不再出现 `HTTP 404`）。

## 数据会自动迁移，不会丢东西

升级后第一次加载时，host 会把存储版本 3 升到 4：

- 每条记忆补上 `scope`（按有无项目推断）、`confidence`、`importance`、`protectionLevel`、`usageCount`、`lastUsedAt`、`evidenceCount`、`currentVersion`、`versions[]`、`evidence[]`。
- 每条记忆自动生成第 1 版（变更类型「新建」，说明「迁移自旧版本数据」）；如果这条记忆当初带来源说明，会同时补一条证据，方便追溯。
- 关系补 `confidence`、`source`、`updatedAt`。
- 新增顶层 `proposals[]`（更新提案）与 `recalls[]`（调用记录），初始为空。

安全性保证：

- 写回前把原文件复制为 `memories.json.bak`；写入走临时文件 + 原子改名。
- 解析失败时文件改名 `memories.json.corrupt-<时间戳>`，不会静默覆盖。
- 旧字段（`category`、`summary`、`body`、`facts`、`legacy.*`）原样保留，不做破坏性清理。

**升级后建议**：打开「全部记忆」扫一眼条数，与升级前一致即可；不确定时直接对比 `memories.json` 与 `memories.json.bak`。

## 行为上的变化

| 之前 | 现在 |
| --- | --- |
| 直接编辑记忆正文就改掉 | 普通记忆留版本；与已确认内容冲突时生成提案，等你确认 |
| 没有保护概念 | 记忆有三种保护级别；「固有约定」的正文改动会被拒绝（`409 protected`），需要你显式解除或确认 |
| 关系只有类型和状态 | 关系多了置信度与来源；被否决的关系不会被无理由重建 |
| 只能手动整理 | 新增 `design_memory_observe` 自动沉淀、`design_memory_recall` 分层检索，界面有整理中心与调用记录 |
| 左侧导航 8 项 | 新增「整理中心」「调用记录」 |

## 关于「自动调用」

2.1 实现了**真实的检索工具与调用日志**：智能体按任务调用 `design_memory_recall`，取用了哪些记忆、什么时候取用，都能在「调用记录」里查到，并会累加记忆的调用次数。

但**没有实现聊天消息的自动注入**——那需要插件接入 DSH 的会话接口，当前版本不在插件可用的稳定接口内。所以文档和界面都不会假装「所有对话都自动带上下文」。如果你希望在每次对话开头自动带上项目约定，可以让智能体在开工时先调一次 `design_memory_recall`，或在提示词里说明「先查知微」。

## 常见问题

**重启后面板还是 404？**
说明 host 没加载成功。看 DSH 日志/插件状态里这条插件的 `fiberPhase`：`failed` 时 `diagnostic` 会写原因（最常见是工具注册契约变化）。先跑 `node tests/dsh-contract.mjs`，它能本地复刻这类失败。

**旧记忆的保护级别为什么是「已确认」？**
迁移时把「已生效 / 已归档」的记忆默认标为「已确认」，普通草稿标为「普通」。你可以逐条改成「固有约定」，也可以在详情栏的「保护级别」里切换。

**升级后 AI 不再直接改我的约定了？**
这是 2.1 的有意设计。固有约定的修改只能由你发起：在详情栏解除保护或接受提案。想临时改一条，可以先把它降级成「普通」。

**版本回滚在哪？**
详情栏的「历史版本」区块，展开后每条版本旁边有「恢复」。恢复本身也会记一个新版本（变更类型「恢复」），所以回滚同样可追溯。
