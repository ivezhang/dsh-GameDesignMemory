# 知微 2.4.0 升级说明

## 改了什么

1. **集合管理**：「主题集合」页右上角新增「管理集合」。每行可以直接改名、改描述、改颜色、改项目，调整成员（勾选后同步增删，不会把没勾的成员全删掉），合并到另一个集合，或删除集合。
2. **保存的视图可以删除**：左侧「保存的视图」每行悬停右侧出现删除按钮。
3. **设置搬进 DSH 设置页**：打开 DSH 的设置，左栏会多出「知微」一节，三块内容——存储位置（当前路径、输入新路径、切换到这里，切换前会在旧位置留一份 `.before-switch` 备份）、整理用的模型（provider / model 两个下拉 + 启用）、数据（导出 JSON、导入 JSON，merge 或 replace）。插件内部的齿轮按钮与设置弹窗已移除。
4. **整理用的模型真正生效**：之前代码读的是 `ctx.llm`（不存在，恒为空），所以下拉里永远是空的、选了也没用。现在通过依赖注入拿到 DSH 的模型运行时；「整理这条」会先用模型做严格 JSON 整理，失败才回落到本地启发式，结果里会标明本次是模型还是本地规则。
5. **两处一直没生效的调用**：集合合并（前端 `sourceId / targetId`）和删除视图（前端 `viewId`）的字段别名现在两边都兼容。

## 数据安全

- 数据版本仍是 **5**，不需要迁移；已有记忆、关系、集合、视图、记忆区都不动。
- 切换存储位置前会把当前文件复制一份 `memories.json.before-switch`；日常保存仍然先写 `.bak` 再原子替换。
- 导入默认 `merge`：按 id 去重，不会覆盖已有记忆；`replace` 才会整份替换（会先写 `.bak`）。

## 如何生效

- 前端（集合管理、视图删除）：刷新页面即可。
- 后端（模型接入、集合合并别名、视图删除别名）：需要**完全退出并重启 DSH**。
- 重启后可在设置里看到模型是否可用：可用时两个下拉会列出 provider 与模型；不可用时提示「当前环境没有可用的模型服务」。

## 已知边界

- 模型只用于「整理这条」的整理建议；本地启发式仍然保留，模型不可用或返回格式不对时自动回落。
- 导入是整份数据的合并 / 替换，没有逐条冲突合并的 UI。
