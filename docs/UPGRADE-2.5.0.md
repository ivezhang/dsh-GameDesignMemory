# 知微 2.5.0 升级说明（V2.4 知识网络改造）

2.5.0 把知微从「记忆管理」升级成「知识网络」：新增知识对象（KnowledgeNode）层，关系网默认画对象、记忆按需展开，交互按 V2.4 规范统一。数据版本 5 → 6，首次启动自动迁移并留备份。

## 一、你会看到的变化

1. **左侧多了「知识网络」**：进去是四个视图（项目 / 工作 / 偏好 / 全局），切换只改筛选，不复制节点。
2. **画布上同时有对象和记忆**：知识对象是双圈 + 类型单字（项 / 系 / 子 / 象 / 流 / 好 / 则 / 法），记忆是实心点；对象带 `+N` 徽章，点一下折叠它的子树，再点展开。
3. **选中对象看对象详情**：类型、状态、范围、项目、属性、流程步骤、父级与子对象、关联记忆、关系；记忆详情里也会显示「它属于哪些知识对象」并可以跳过去。
4. **建立关系有了正式入口**：工具栏「建立关系」→ 选目标 → 选关系类型（28 种，分五组）→ 实时看到一句自然语言预览（例如「哥布林 → 掉落 → 铁矿石」）→ 需要时点「反向」→ 保存。自反、类型不匹配、层级成环、重复关系都会被拦住并说明原因。
5. **对象可以合并**：详情里点「合并」，对比两个对象的字段后保留主对象，关系与关联记忆迁过去，被合并的标记为「已合并」并可追溯。
6. **整理中心多了两张卡**：「候选知识对象」（确认即转正）和「疑似重复的知识对象」（一键进合并）。
7. **流程步骤可以调顺序**：编辑工作流程对象时，每一步右侧有上移 / 下移。
8. **可以纠正 AI 对你的理解**：在用户偏好对象详情里点「纠正 AI 的理解」——缩小范围 / 扩大范围 / 标记不再适用 / 说明这只是一次性要求，纠正会写回该对象。

## 二、数据安全

- 首次加载会把数据从版本 5 迁到 6：为每个已有项目补一个「项目」知识对象，其余数据（记忆、版本、证据、提案、召回记录、集合、记忆区、布局、保存视图）原样保留。
- 迁移前写 `memories.json.bak`；解析失败仍会另存 `.corrupt-<时间戳>` 再从空库开始，不会覆盖坏文件。
- 删除语义三级：解除关联（记忆还在）、归档（可恢复）、彻底删除（二次确认）。合并不会物理删除来源对象，只标记 `status: merged` + `mergedIntoId`。

## 三、如何生效

- 前端改动：刷新页面即可。
- 后端改动（新增节点存储、关系双端点、6 → 版本迁移、recall 返回 nodes）：**需要完全重启 DSH**（退出进程再启动，不是刷新页面）。
- 重启后 `GET /design-memory/api` 应返回 `"version": 6` 且带 `nodes` 字段。

## 四、验证结果

- host：91 tests 全过（含 16 条知识对象用例：建对象、重复提醒、关系校验、合并、归档恢复、召回命中对象）
- 渲染：162 checks 全过（含 14 条知识网络交互）
- 契约：7 / 7；迁移：16 / 16；静态审计：干净

## 五、已知边界

- 画布没有节点展开的位移动画，只有淡入与呼吸光晕（刻意的轻量取舍）。
- 不提供「展开全部」，只有逐层折叠；节点上限 1200。
- 自动观察只产出「候选对象」，不会自动建正式对象——避免图谱被低质量节点填满。
- 对象级版本历史尚未实现（记忆级已有版本与证据）。
- 偏好纠正写回对象属性，不单独生成一条演进记录。
- 真实鼠标拖拽手感、`Space` 平移、`Shift` 框选等**需要你人工走查**：自动化只验证了数据流与组件树，不能代替手感确认。
