# 2.6.4 升级说明：整理中心性能修复 + 数据层实测

## 修掉的问题

整理中心（找重复记忆）原本是全量两两比对：1000 条记忆要掏 50 万次比较，每次还重算两边的正文主题词，实测 **7.8 秒**。

现在改成三步：先按记忆类型分桶（不同类型根本不可能重复），再用「标签对」建倒排索引（共享两个以上标签的两条记忆必然落进同一个桶），桶内再算主题词重合，且每条记忆的主题词只算一次。同样数据从 **7837ms → 69ms**，判断规则一个字没改。

知识对象的重复检测也顺手加了主题词缓存与类型分桶。

## 新增实测脚本

`node tests/perf.mjs` 会在临时库里造压测数据（300 个知识对象、1000 条记忆、300 条关系），逐项量耗时并写 `docs/PERF.md`：

| 场景 | 耗时 |
| --- | --- |
| 首次读取整库（加载 + 规范化） | ~49ms |
| 再次读取整库 | ~16ms |
| 搜索「掉落」 | ~2ms |
| 按任务召回 10 条 | ~57ms |
| 整理中心报告 | ~69ms |
| 保存 300 个节点布局 | ~46ms |

预算内 7 / 7 达标。注意这只覆盖数据层与接口层，浏览器里的绘制耗时仍要按 WALKTHROUGH 用 DevTools 看。

## 兼容性

数据版本仍是 6，无需迁移；只是把重复判断的算法换成等价的更快实现，已有测试（含重复识别用例）全过。
