# 知微 2.6.9 升级说明 · 全局撤销

## 这一版解决什么

之前只有「关系」「集合成员」能撤回一小步；**删记忆、删对象、批量改动只能靠二次确认**，一旦点错，只能从导出的 JSON 备份里捞。这一版加了真正的全局撤销：

按一次 **Ctrl / Cmd + Z**，整库回到上一次写操作之前。

## 能撤销哪些操作

记忆的新建 / 修改 / 删除 / 改状态 / 收藏 / 打标签 / 归档 / 恢复 / 保护级别 / 版本回滚 / 补证据 / 接受提案 / 合并、关系的新建 / 修改 / 确认 / 删除、集合的新建 / 删除 / 成员 / 合并 / 拆分、项目的新建 / 删除 / 排序、记忆框的新建 / 删除 / 同步、知识对象的新建 / 删除 / 归档 / 恢复 / 合并 / 关联记忆 / 版本回滚，以及整库导入。

**不能撤销**：拖动节点产生的位置保存（`layout-save`，会连续触发把栈冲满）；按任务召回、观察沉淀、搜索、导出这类只读或日志动作；关闭 DSH 后栈会清空。

## 用起来是什么样

- 全局：在页面任意空白处按 Ctrl / Cmd + Z。
- 局部：硬删知识对象、批量删除记忆后，右上角提示里直接有「撤销」按钮，点一下等于按一次快捷键。
- 栈深 5 步：连续撤销最多退回 5 次写操作，再按会提示「没有可以撤销的操作了」。
- 在输入框里、或有弹窗打开时，Ctrl + Z 仍然是文本框自己的撤销，不会把整库退回去。

## 实现要点（给维护者）

- 宿主 `parts/host/40-apply.js`：`persist()` 旁边的 `undoStack` / `UNDOABLE_ACTIONS` / `cloneState()` / `replaceState()` / `undoInfo()`；POST 里 `action === 'undo'` 单独分支（不吃 `applyAction`，直接换回快照再走一次正常存盘）。
- 快照是整库深拷贝，写操作前留、写成功后入栈；超过 5 条从头裁掉。
- GET 与 POST 响应都带 `undo: {count, limit, last}`，客户端据此决定 Ctrl + Z 是撤销还是提示。
- 撤销不单独造工具给 AI：工具 schema 的 action 枚举**没有** `undo`，避免模型随手回滚人的改动；只有界面与本地 HTTP 接口能触发。
