# 升级说明 2.7.0 — 项目空间不再乱建，老记忆框能删了

发布：2026-11-26 · 数据版本仍是 6（无迁移）· 需要重启 DSH

这一版没有新模型、没有新概念，只修三个一直有人踩的坑，外加一个一直在缺的操作：**项目空间多选，批量并进另一个项目**。

## 一、修：重命名 / 删除项目时，会多建出一个同名项目

### 现象

右键项目空间点「重命名」，改了名字点保存，结果多出一个「N2」项目；点「删除」，也留一个「N2」下来。你的库里因此堆了几个空项目。

### 原因

重命名弹窗与「新建项目」弹窗在同一个判断下同时挂载（都判 `modal.type === "project"`），新建弹窗叠在上层，你点的保存实际提交的是「新建」。

### 现在

- 两个弹窗按模式分开：改名/删除只出 `ProjectDialog`，新建只出 `NameDialog`，一次只弹一个。
- 顺带修好项目空间标题栏的 `+`：之前它调的方法名和面板传的对不上，点了直接报错。

## 二、修：删除项目时，知识对象 / 记忆区 / 视图会被留在空气里

之前删除项目只把**记忆**和**集合**迁到兜底项目，知识对象、记忆区、保存的视图还挂着已经删掉的 `projectId`——它们在别的项目里看不见，也不属于任何项目。

现在删除项目会把记忆、知识对象、记忆区、保存的视图一起迁到兜底项目，并清掉这个项目自带的项目对象与挂在它身上的关系，不留悬空关系。

## 三、新：项目空间多选，批量并进一个项目

项目空间标题栏多了一个「批量选择」按钮：

1. 点「批量选择」，项目行左边出现勾选框；
2. 勾上要合并的几项（通常就是 bug 造出来的那几个空项目）；
3. 列表上方出现批量条——选一个目标项目，点「迁移并合并」；
4. 源项目的记忆、知识对象、记忆区、集合、保存的视图都迁进目标项目，源项目本身连同它的项目对象一起消失。

规则：目标项目不能是被勾选的项目之一；至少要留一个项目。这个操作也能 `Ctrl / Cmd + Z` 退回。

## 四、修：老版本画的记忆框，点不到也删不掉

### 现象

关系图里那些 1.x / 2.2 时代画的老框（只有一圈虚线轮廓、没有矩形框体），鼠标点上去毫无反应，按 `Delete` 也不删。右边「记忆区」列表里明明有它。

### 原因（两个叠加）

1. 老框只画了虚线轮廓 `path`，没有可点的命中区，而整个帧层是 `pointer-events: none`——浏览器里根本点不到它；
2. 点中间的「记忆区胶囊」只选中了框里的记忆，没有把「当前记忆区」记下来，于是 `Delete` 时框架层拿不到要删的对象，什么都不会删。

> 顺带说明为什么测试一直绿：渲染测试是直接调轮廓的 `onClick`，绕过了浏览器真实的命中测试。这次给这类断言补了「走命中区」的用例。

### 现在

- 老框多了一圈透明加粗的命中带（`stroke-width: 16`），虚线轮廓本身也恢复接收指针事件；
- 点选框（点轮廓或点胶囊都行）之后，关系图工具条会出现两个按钮：**删除记忆区**（只删框，记忆保留）与**改名**；
- `Delete` / `Backspace` 也能删，删完顺手清掉框里的多选状态。

## 五、这次没做的

- 项目空间的「批量选择」只做合并迁移，没有批量删除（删除仍走单个项目的二次确认）；
- 撤销栈深度仍是 5、仍不跨重启；
- 老框的「拖动整块」仍然只对有 `rect` 的框生效——老框想挪位置，先在工具条上用「画框」重画一个，或在关系图里拖动它框住的记忆后重新保存布局。

## 六、升级步骤

1. 完全退出 DSH（不是关窗口）再打开，插件才会加载新宿主代码；
2. 打开知微 → 关系图，点一下那个老框，工具条里应该出现「删除记忆区」；
3. 打开项目空间 → 「批量选择」，把 bug 造出来的空项目勾上，迁移并合并到主项目；
4. 顺手按一次 `Ctrl / Cmd + Z` 确认撤销还正常。

数据版本仍是 6，不需要迁移，升级前建议在设置里导出一份整库 JSON 备份。
