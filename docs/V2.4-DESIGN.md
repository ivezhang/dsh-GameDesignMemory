# 知微 2.5.0（V2.4 知识网络改造）设计与迁移说明

本文件对应 V2.4 需求书（多维知识网络 / 交互规范 / 自动记忆升级），记录架构变更、数据模型、迁移结果、交互清单、测试结果与已知未完成项。

## 一、架构变更

改造前的模型是「记忆（Memory）为中心」：一条记忆带类型、领域、状态、版本、证据、关系，关系网画的就是记忆。V2.4 起改为「知识对象（KnowledgeNode）+ 记忆（Memory）」双层：

- **KnowledgeNode** 描述稳定的实体：项目、系统、子系统、业务概念（怪物 / 装备 / 技能 / 副本…）、工作流程、用户偏好、设计原则、设计方法。
- **Memory** 继续承载具体信息：决策、规则、假设、问题、方案、参考、数值、复盘、流程约定、习惯、通用约定、项目背景、临时事项。一条记忆可以关联多个知识对象，一个对象可以包含多条记忆。
- **Relation** 升级为「双端点」关系：两端各自可以是一条记忆（memory）或一个知识对象（node），也允许对象↔记忆混连。

三层都在同一份存储里，仍然只有一个数据文件：

```
{ version: 6,
  projects, entries, nodes, relations, collections, frames, layout,
  views, proposals, recalls, stats }
```

前端结构：左侧导航（新增「知识网络」）→ 中间工作区（`KnowledgeView`：项目 / 工作 / 偏好 / 全局四个视图，共用同一个画布）→ 右侧详情（对象详情 `NodeDetail` 与记忆详情 `DetailRail` 互斥，选中谁显示谁）。视图切换只改变筛选，不复制节点。

## 二、数据模型

### KnowledgeNode

| 字段 | 说明 |
| --- | --- |
| id | `knd_…` |
| title / description | 名称与描述 |
| nodeType | project / system / subsystem / concept / workflow / preference / principle / method |
| scope | global / project（适用范围） |
| projectId | 所属项目 |
| parentNodeId | 父级对象（用于项目结构树与画布折叠） |
| attributes | `[{ label, value }]`，类型专属扩展属性 |
| steps | 仅 workflow：`[{ id, title, note, memoryIds }]` |
| aliases | 别名，用于自动匹配中文/英文叫法 |
| tags | 标签 |
| status | candidate 候选 / active 有效 / archived 已归档 / merged 已合并 |
| confidence / importance | 0–1 |
| sourceMemoryIds / relatedMemoryIds | 来源记忆与关联记忆 |
| mergedIntoId | 被合并到哪个对象 |
| origin | 来源（手动 / AI 观察 / 导入） |
| createdAt / updatedAt | 时间 |

### Memory 新增字段

`nodeIds`（关联对象）、`parentNodeId`（主要归属对象）。其余字段（type / domains / status / versions / evidence / protectionLevel / usageCount / lastUsedAt …）保持 2.4 不变。

### 关系

| 字段 | 说明 |
| --- | --- |
| sourceType / sourceId | memory 或 node + id |
| targetType / targetId | 同上 |
| relationType | 28 种，分五组（层级 / 业务 / 流程 / 偏好原则 / 知识） |
| confidence / evidence / source | 置信度、依据、来源（ai / user） |
| status | suggested / confirmed / rejected |

关系类型分组（`META.relationGroups`）：

- 层级：CONTAINS、BELONGS_TO、PART_OF
- 业务：APPEARS_IN、USES、DROPS、REQUIRES、CRAFTED_FROM、AFFECTS、DEPENDS_ON、BALANCED_AGAINST
- 流程：FOLLOWS、PRECEDES、NEXT_STEP、TRIGGERS、PRODUCES、EXCEPTION_TO
- 偏好原则：PREFERS、AVOIDS、APPLIES_TO、GUIDES、CONSTRAINS
- 知识：RELATED_TO、DERIVED_FROM、REFERENCES、CONFLICTS_WITH、SUPERSEDES、REFINES

保存关系时校验：自反（source==target）→ 400；两端类型不适用（如 DROPS 只允许 concept→concept）→ 400；层级关系成环 → 400；重复（对称关系含反向）→ 复用已有行、`created: false`。每条关系都能生成一句自然语言说明（`describeRelation`），界面上「建立关系」会实时预览，例如「哥布林 → 掉落 → 铁矿石」。

## 三、数据迁移（4 → 5 → 6）

`migrateStore` 是幂等的，每次加载都会把旧结构补齐：

1. 每个项目自动生成一个 `nodeType: 'project'` 的知识对象（标题取项目名），已有项目节点则跳过。
2. 关系去重键从「记忆×记忆×类型」改为「sourceType + sourceId + targetType + targetId + relationType」；旧的 `{to, label}` 链接与 `sourceMemoryId/targetMemoryId` 关系照常读入并保留兼容字段。
3. 记忆与对象的双向关联以 `node.relatedMemoryIds` 为主表，加载后反推 `entry.nodeIds`，避免两边不一致。
4. 集合成员允许是记忆或知识对象；记忆区（frames）仍是空间容器，位置与业务归属互不影响。
5. 版本、证据、提案、召回记录原样保留；迁移前写 `.bak`，迁移后仍保留 `.corrupt-<时间戳>` 兜底路径。
6. 迁移不创建任何「填充用」的低质量对象——只为既有项目补一个项目节点，其余对象都由你或 AI 的观察显式产生。

## 四、UI 与交互变更

### 知识网络（新）

- 顶部四个视图：项目 / 工作 / 偏好 / 全局；切换只改筛选。
- 画布同时画知识对象（双圈 + 类型单字）与记忆（实心圆点），对象可折叠：`+N` 徽章点一下折叠子树，再点展开；折叠只影响显示。
- 单击节点选中并开右侧详情；`Ctrl/Cmd` 或 `Shift` 点击多选；双击进入对象的局部视图（聚焦上下游）；点空白取消选择并收起详情；`Space + 拖动` 平移，`Shift + 拖动空白` 框选，滚轮以指针为中心缩放。
- 选中对象后右侧显示：类型 / 状态 / 范围 / 项目、属性、流程步骤、父级与子对象、关联记忆（可增删，删除只解除关联）、关系（方向、类型、确认状态）。
- 对象操作：新建（类型 / 上级 / 范围 / 描述 / 别名 / 属性 / 流程步骤）、编辑、归档、恢复、合并（对比字段后保留主对象）、彻底删除（二次确认）。重名与高相似对象会先提示，默认不合并。
- 关系：工具栏「建立关系」→ 选目标（对象或记忆）→ 选 28 种关系之一 → 实时自然语言预览 + 「反向」按钮 → 保存。类型不适用、成环、重复都会被拦住并说明原因。
- 工作流程对象：步骤可增删，编辑弹窗里每步带上移 / 下移按钮；删除步骤只删流程结构，不动关联记忆。
- 用户偏好对象：详情里有「纠正 AI 的理解」——缩小范围、扩大范围、标记不再适用、说明这是一次性要求，纠正会作为属性写回该对象并可追溯。

### 跨页面

- 记忆详情里新增「所属知识对象」徽章，可跳回对象；对象详情里可跳回记忆，双向可达。
- 「全部记忆」搜索同时命中知识对象，结果单独分栏显示并可点开。
- 整理中心新增两张卡：候选知识对象（确认即转正）、疑似重复的知识对象（直接进合并）。
- 关系图页新增「记忆区」工具（画框 → 起名 → 框内自动归属），与知识网络共用同一套画布能力。

### 反馈与删除语义

- 保存节点 / 关系 / 记忆统一走 `mutate`，成功后刷新整份状态并弹对应提示；失败保留输入并显示错误码文案。
- 删除分三级：解除关联（记忆仍在）、归档（可恢复）、彻底删除（二次确认）。
- 关系建议（AI）可以确认、拒绝；新建关系默认是「已确认」，AI 自动观察产生的是「建议」。

## 六、实际交互走查状态（如实）

- **已自动化验证**：上表所有断言，都是真实渲染组件树 + 真实 host handler（假 DOM、真实数据流）。
- **未完成交互验收（需要人工在浏览器里点）**：真正的鼠标拖拽/滚轮手感、`Space` 平移与 `Shift` 框选的体感、动画流畅度、长内容下的视觉拥挤程度、多显示器与缩放比下的布局。这些不满足「只测了逻辑就不算交互验收」的要求，因此明确标为未完成。
- 建议的人工走查路径：进入知识网络 → 依次点四个视图 → 点一个对象查看详情 → 新建一个 concept 并设父级 → 建立一条 DROPS 关系看预览 → 折叠/展开子树 → 框选两个节点批量加集合 → 在记忆详情里跳到所属对象 → 整理中心确认一个候选对象。

## 七、已知边界与未完成项

1. 画布动画只有淡入与呼吸光晕，没有节点展开的位移动画（按需求「轻量、不阻碍连续操作」取舍）。
2. 「展开全部」未提供，只有逐层折叠/展开；节点规模上限 1200，超过会拒绝新建而不是分页。
3. 关系类型的「适用性规则」只覆盖明显不合理组合，仍有少量组合需要人工判断。
4. 节点位置与知识数据分离保存在 `layout`，拖动结束 700ms 防抖落盘；若在此期间关闭页面，最后一次位移可能丢失。
5. 自动观察只做「匹配已有对象 / 产出候选」，不会自动创建正式对象；候选需要你确认（这是刻意的，避免图谱被填充物污染）。
6. 偏好「纠正 AI 的理解」目前写回属性，不单独建一条演进版本；对象级版本历史尚未实现（记忆级已有）。
7. 批量操作只提供「加入集合 / 批量状态 / 批量归档」，未做批量改父级或批量合并。
8. 未接入真实的大模型自动归纳对象结构（模型只用于「整理这条」的单条整理，失败回落本地启发式）。

## 八、兼容性

- 旧六个工具 `design_memory_search` / `write` / `suggest` / `analyze` / `observe` / `recall` 全部保留，`search` 新增 `nodeType`、`frameId` 参数并额外返回知识对象；`recall` 新增 `frameId`，返回值新增 `nodes`。
- 记忆区（frames）、集合（collections）、保存视图、导入导出、存储切换、模型选择全部保留。
- 数据版本 5 → 6 自动迁移，首次加载写 `.bak`；`memories.json` 仍是唯一数据文件。
